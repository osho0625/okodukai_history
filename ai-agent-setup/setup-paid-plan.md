## なぜ Kiro Pro なのか

### 1. クレジット量が十分

| プラン | クレジット/月 | 目安 |
|---|---|---|
| Free | 50 | 月1〜2機能の設計駆動が限界 |
| **Pro** | **1,000** | **週5〜10機能の設計駆動が可能** |
| Pro+ | 2,000 | ヘビーユーザー向け |

1,000クレジットあれば:
- aide-powers でフル設計駆動開発: 週に5〜10機能
- 軽い質問・コード説明: 数百回
- 子供が毎日「〇〇作りたい」と言っても余裕

### 2. 子供の教育に最適

- **GUIベース**: VS Codeベースで見た目がわかりやすい（Claude Codeはターミナルのみで子供にはハードル高い）
- **Spec駆動開発**: 「何を作りたい？」→ 要件整理 → 設計 → 実装 の流れが可視化される
- **aide-powers連携**: ソフトウェア開発のプロセス（企画→設計→実装→レビュー）を自然に体験できる
- **考える力が育つ**: いきなりコードが出てこないので「何を作るか」を自分で考える習慣がつく

### 3. Cline + Ollama との使い分け

| シーン | 使うツール |
|---|---|
| 新しい機能を設計から作る | Kiro Pro + aide-powers |
| 「この関数の意味教えて」等の軽い質問 | Cline + Ollama（クレジット節約） |
| オフライン・ネット不安定な時 | Cline + Ollama |
| 子供が自由に試行錯誤 | Cline + Ollama（無制限なので気軽） |
| 子供に設計プロセスを教えたい時 | Kiro Pro + aide-powers |

## Kiro Pro のクレジット節約術

月1,000クレジットをうまく使うコツ:

1. **考えをまとめてから質問する** — 「あ、やっぱり違う」で再質問するとクレジットが無駄になる
2. **軽い質問は Cline + Ollama に逃がす** — 「この文法の意味は？」レベルはローカルLLMで十分
3. **Autoモデルを使う**（デフォルト） — Sonnet 4.5 直指定より Auto の方がクレジット効率が良い（約23%節約）
4. **Specモードはタスクリストから「Start task」で実行** — チャットで指示するよりクレジット消費が少ない
