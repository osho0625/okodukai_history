# 共通スキル詳細

複数のワークフローから呼び出される再利用可能なスキル群。本ファイルでは共通スキルの位置づけ、
フェーズスキルとの違い、分類の考え方をまとめる。

## 共通スキルとは

| 種別 | 配置 | 命名規則 | 呼び出され方 |
|---|---|---|---|
| フェーズスキル | `skills/fs-{workflow}-phase{N}-{name}/SKILL.md` | `fs-` プレフィックス + ワークフロー名 + フェーズ番号 | ワークフロー本体として 1 回ずつ順序通りに呼ばれる |
| **共通スキル** | `skills/{name}/SKILL.md` | 機能名そのまま（例: `design-gate`、`doc-sync`） | フェーズスキルや他の共通スキルから何度でも呼ばれる |
| メタスキル | `skills/{name}/SKILL.md` | 機能名そのまま | ワークフロー横断・運用基盤として常時動く（`rules-distribute` / `task-orchestration` 等） |

共通スキルとメタスキルは命名上の区別がなく、本章では「共通スキル」として一括して扱う。
ハブスキル（`using-aide-powers`）の機構と `aide-powers-guide`、`rules-distribute` の動作詳細は
[第1章](../../01-system-platform/) の責務であり、本章では呼び出し関係のみを扱う。

## フェーズスキルとの違い

| 観点 | フェーズスキル | 共通スキル |
|---|---|---|
| 呼ばれる順序 | ワークフロー内で固定の順序 | 必要に応じて何度でも、複数のフェーズから |
| 進捗管理 | 進捗ファイルを直接編集できる（メタ情報の例外） | 進捗ファイルを編集しない |
| ユーザー対話 | ユーザーへのヒアリング・合意取得を担う | 原則ユーザーと直接対話しない（呼び出し元が対話を担う） |
| サブエージェント委譲 | 自分で委譲を組み立てる | 一連のロジックを自己完結で持つ（必要なら自身もサブエージェントを使う） |
| Iron Law の宣言 | フェーズスキル固有の Iron Law を持つ | 共通の品質ルール（モック禁止、コーディング規約等）を集約する |

## 分類

本フォルダでは共通スキルを次の 3 つに分類して詳細を記述する。

| 分類 | 内容 | ファイル |
|---|---|---|
| 配布・運用系 | ルール配布、進捗管理、コミット、ドキュメント管理、ゲート判定、QA ディスパッチ等の基盤スキル | [`infrastructure.md`](./infrastructure.md) |
| 設計系 | 各設計フェーズの本処理（要件定義 / システム要件 / ユースケース / GUI / DDD / オブジェクト / インフラ IF / プログラム構成）を担う共通スキル | [`design.md`](./design.md) |
| 実装系 | コーディング規約、タスク分解、多段階レビュー、各レビュー観点を提供する共通スキル | [`impl.md`](./impl.md) |

## 使い分けのガイド

- **「どの設計書を作るか」が決まっているなら** → 設計系の共通スキルを呼ぶ。フェーズスキルが create / fix / delta / reverse / update のどのモードで呼ぶかを指示する。
- **「設計書ゲート PASS / FAIL を判定したい」なら** → 配布・運用系の `design-gate`。
- **「ワークフロー完了時にコミットしたい」なら** → 配布・運用系の `git-commit-workflow`（直接 `git commit` は禁止）。
- **「実装後にコードレビューしたい」なら** → 実装系の `multi-stage-code-review` がパイプライン全体を、`code-quality-review` / `design-review`（共通スキル `import-review`）/ `error-handling-review` / `test-review` が観点を提供する。

各ファイル内では、共通スキルごとに「目的」「呼び出し元」「メインプロセスの要点」「Iron Law」をまとめる。

## エージェントとの関係

共通スキルはサブエージェントに委譲することがあるが、共通エージェント（`agents/` 配下の名前付き定義）と
共通スキルは別概念である。共通エージェントの詳細は [`../04-agents/`](../04-agents/) を参照。

たとえば実装系の `multi-stage-code-review` 共通スキルは、ホワイトリスト3エージェント
（`micro-impl-agent` / `design-review-agent` / `code-review-agent`）の呼び出し順序とパイプラインを規定するが、
エージェント自身の役割定義・モード・ステータス運用は `agents/{name}.md` 側に集約されている。
