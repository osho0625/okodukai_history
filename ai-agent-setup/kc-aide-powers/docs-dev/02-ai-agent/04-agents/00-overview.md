# 共通エージェント詳細

aide-powers が `agents/` 配下で名前付き定義として提供するサブエージェント群。
複数のワークフローから共有され、コンテキスト分離・ツール制限・並列実行が可能な実作業の担い手である。

本フォルダでは共通エージェントを 2 分類で詳細化する。

| 分類 | 内容 | ファイル |
|---|---|---|
| 実装系エージェント | 実装ループの実作業を担うホワイトリスト3エージェント | [`implementation-agents.md`](./implementation-agents.md) |
| QAレビューアーエージェント | 設計書の品質を判定するエージェント群 | [`qa-agents.md`](./qa-agents.md) |

## 共通エージェントとは

| 観点 | 共通エージェント | フェーズスキル / 共通スキル |
|---|---|---|
| 定義場所 | `agents/{name}.md` | `skills/{name}/SKILL.md` |
| 起動方法 | フェーズスキル / 共通スキルから委譲（プラットフォーム固有のサブエージェント呼び出し） | `Skill` ツール（プラットフォーム別に名称が異なる） |
| コンテキスト | 親と分離され、独立して動作する | 親のコンテキストに合流する |
| 主な責務 | 実作業（実装、レビュー、QA 判定） | 規約・ルール・処理ロジックの集約 |

ワークフロー本体（フェーズスキル群）は **進行管理とユーザー対話** に専念し、
**実作業はサブエージェント委譲または共通スキル経由** で行う。これは aide-powers の
グローバルルール「ワークフローの実作業禁止」に対応する。

## ホワイトリスト3エージェント

実装系ワークフロー（実装 / 変更 / バグ修正 / リファクタリング）の工程チェック表で
**実行担当として認められる** のは次の3エージェントだけである。

- `micro-impl-agent`
- `design-review-agent`
- `code-review-agent`

オーケストレーター自身が工程チェック表の工程行を更新すること、自己チェック用サブエージェントを
新規に作って通過させることは禁止される。

## ステータス 4 種

`micro-impl-agent` を中心に、サブエージェントが返す完了報告のステータスは以下の 4 種で統一されている。

| ステータス | 意味 | 呼び出し元の動作 |
|---|---|---|
| `DONE` | 正常完了。次工程へ進める | 通常通り次工程へ |
| `DONE_WITH_CONCERNS` | 完了したが懸念事項あり | 懸念をユーザーに提示・記録し、必要なら追加対応 |
| `NEEDS_CONTEXT` | 情報不足で続行不可 | 不足情報を補って再委譲 |
| `BLOCKED` | 環境・依存等の阻害で実行不可 | 阻害要因を解消するか、ワークフローを中断する |

QAレビューアーエージェントは別の判定軸（`APPROVED` / `REJECTED`）を返す。詳細は
`qa-agents.md` を参照。

## サブエージェント委譲の原則

- **コンテキスト分離**: 親の会話履歴をそのままサブエージェントに流さない。タスク遂行に必要な情報だけを渡す（§7-2）。
- **ツール制限**: エージェントの frontmatter に `tools` を記載してツール権限を絞ることが可能。
- **並列実行**: 独立したタスクは並列に委譲してよい（`task-orchestration` 共通スキル経由）。
- **修正は実装エージェントが行う**: レビュー結果に基づく修正は `code-review-agent` / `design-review-agent` ではなく `micro-impl-agent` の `fix` / `fix_test` モードが担当する。

## 行動規範の共通項

- 実作業以外への踏み込み禁止: 実装エージェントはレビューを行わない。レビューエージェントは修正を行わない。
- ダミー実装・モック・スタブの使用禁止（テスト用ダミーは設計上の DI 切り替えとして例外）。
- 設計書を読まずに作業を始めない。
- 設計書との乖離を発見したら、自分で設計を変更せず報告する。
