# 設計書充実度チェック プロンプトテンプレート

## 使用方法

`{file_path}` を対象ファイルの実パスに置換してサブエージェントに渡す。

## プロンプト

```
以下のファイルを読み、設計書として機能するかを判定せよ。

対象ファイル: {file_path}

## 判定基準

FAIL（以下のいずれかに該当）:
- ファイルが存在しない
- 空ファイル
- スタブのみ（TODO、placeholder、「後で記述」等）
- 内容が断片的で、実装時の設計判断の根拠にならない
- 見出しだけあって中身がない

PASS:
- 上記FAILに該当せず、実装の根拠として参照できる具体的な情報が記載されている

## 出力形式

1行目: PASS または FAIL
2行目以降: 判定理由（1〜3文で簡潔に）

例:
PASS
プロジェクトのフォルダ構成、各ファイルの役割、レイヤー間の依存方向が具体的に記載されている。

例:
FAIL
見出し構造のみで、具体的な技術選定やフォルダ構成の記載がない。設計判断の根拠にならない。
```
