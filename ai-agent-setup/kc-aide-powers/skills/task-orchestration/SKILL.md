# task-orchestration

## Process

**Step 1:** ユーザーから聞き取りを行い以下を明確にする:

   | 項目 | 必須度 | 内容 |
   |---|---|---|
   | 目的 | MUST | 最終的に目指す結果 |
   | 成果物 | MUST | 作成するもの |
   | 情報 | SHOULD | 目的達成に必要な情報 |
   | ツール | SHOULD | 利用できるツール |
   | 手法 | SHOULD | ユーザーから作業手順の説明があればそれを確認 |

**Step 2:** 計画書を作成する（「計画書の作り方」章に従う）
- `.aide/task-plans/{plan-name}/plan.md` に書き出す
- 計画書には以下を必ず含める:
  1. 要求（目的・成果物・情報・ツール・手法）
  2. 計画（プロセス分解、output/next）
  3. 実行結果テーブル
  4. 状態管理表（全件を1つの表にまとめ、ユニークな通し番号を振る）
- サブエージェントへのプロンプトテンプレートは **別ファイル** `.aide/task-plans/{plan-name}/prompt-template.md` に書き出す
  - plan.md にテンプレートを埋め込むと plan.md が肥大化し、サブエージェントが状態管理表を更新する際の str_replace が不安定になる
  - plan.md からは `prompt-template.md を参照` と記載するだけでよい

**Step 3:** 計画書の内容をユーザーに確認してもらう
- ユーザーに提示し、合意を得る

**Step 4:** 計画に従って実行する:
- プロンプトテンプレートの `{変数}` を実行時に埋めてサブエージェントに渡す
- 各ステップの output を確認してから next に進む
- 並列実行可能なプロセスはサブエージェントを同時起動する
- 分岐条件に該当した場合は指定のステップに戻る
- 各プロセス完了時に計画書の status を更新する
- 全ステップ完了後、ユーザーに結果を報告する
- 完了後、計画書ファイルを削除するかユーザーに確認する（残す場合はそのまま保持）

## 計画書の作り方

### 原則

- 目的達成に必要なプロセスを細かく分解する
- 各プロセスに output（成果物）を定義する
- output に応じた next フロー（次のステップ、分岐条件）を決める
- 並列実行可能なプロセスを特定する
- 並列実行可能なプロセスは計画段階で対象を洗い出し並列実行計画を立てて、
　中断再開できるように実行状態管理表を作成する
- **状態管理表は1つにまとめる**: 複数バッチ・複数WFにまたがる場合でも、全件を1つの表にまとめてユニークな通し番号（ID）を振る。サブエージェントが自分の担当行を迷わず特定できるようにする
- **サブエージェントへのプロンプトテンプレートは別ファイルに書き出す**: `.aide/task-plans/{plan-name}/prompt-template.md` として作成する。plan.md にテンプレートを埋め込むとファイルが肥大化し、状態管理表の str_replace が不安定になるため。テンプレートには以下を含める:
  - 担当タスクの特定情報（ID、対象ファイル等）
  - 作業内容の具体的な手順
  - 参照すべき情報（対応表、判定用一覧等）— サブエージェントがディレクトリ一覧取得等の追加ステップを踏まなくて済むよう、テンプレート内に直接埋め込む
  - 完了後に計画書の状態管理表を更新する指示（IDと更新内容を明示）

### 保存先

`.aide/task-plans/{plan-name}/plan.md`

`{plan-name}` は目的を短くkebab-caseにしたもの。実行中はこのファイルのステータスを更新する。

## サブエージェントへのプロンプトテンプレート

**別ファイル `.aide/task-plans/{plan-name}/prompt-template.md` に書き出すこと。**
plan.md には「プロンプトテンプレート: `./prompt-template.md` を参照」とだけ記載する。

以下をサブエージェントに渡す。`{変数}` は実行時に埋める。

**必須: 状態管理表の更新指示をプロンプトテンプレートに必ず含めること。**
サブエージェントは以下の3段階で状態管理表を更新する:
1. **作業開始時**: 自分の行の status を `🔄 in-progress` に変更する
2. **作業完了時**: 自分の行の status を `✅ done` に変更し、output に結果を記入する
3. **失敗時**: 自分の行の status を `❌ failed` に変更し、output にエラー内容を記入する

この3段階の更新指示がプロンプトテンプレートに含まれていない場合、状態管理表が更新されず中断再開が不可能になる。

## Rules

- **計画のユーザー合意**: Step 2の計画をユーザーに提示し、合意を得てからStep 4に進む
- **サブエージェントへの指示は最小限**: 各サブエージェントには必要な情報のみ渡す。親の会話履歴全体を渡さない
- **結果の更新**: 計画書の結果の項目を実行ごとに必ず更新する
- **失敗時のリトライ上限**: サブエージェントが失敗した場合、2回リトライしてダメならユーザーに報告する
- **一括実行禁止**: 計画で分割したタスクはサブエージェント１つに１件とする。サブエージェント１つに複数タスクを一括実行させることは禁止する
- **さらに複雑なタスクの対応**: すぐに計画を立てることができない場合は、task-orchestrationスキルを複数回呼び出して、段階的に解決する計画を立てること

## Red Flags - STOP

| Red Flag | なぜ危険か |
|---|---|
| 計画書に並列実行計画・状態管理表を書かずに実行を開始しようとした | 中断再開ができない。テンプレートの並列実行管理セクションを必ず含めること |
| 計画書をユーザーに提示せずに実行を開始しようとした | ユーザー合意なしの実行は Rules 違反。計画書を提示し「進めてよいですか？」と確認すること |
| 計画書のフォーマットを独自に簡略化した（output/next を省略、状態管理表を省略等） | テンプレートの全項目を埋めること。「シンプルだから省略」は理由にならない |
| 状態管理表を複数に分割した | サブエージェントが自分の担当行を特定できない。全件を1つの表にまとめてユニークIDを振ること |
| プロンプトテンプレートなしでサブエージェントを起動しようとした | ざっくりした指示ではサブエージェントが失敗する。具体的な手順・参照情報・状態管理表更新指示を含むテンプレートを作成すること |
| プロンプトテンプレートに状態管理表の更新指示（開始時 🔄 / 完了時 ✅ / 失敗時 ❌）が含まれていない | サブエージェントが状態管理表を更新しないと、中断再開時にどこまで完了したか不明になる。3段階の更新指示を必ず含めること |
| プロンプトテンプレートを plan.md 内に埋め込んだ | plan.md が肥大化し、サブエージェントの状態管理表 str_replace が不安定になる。必ず別ファイル `prompt-template.md` に書き出すこと |
