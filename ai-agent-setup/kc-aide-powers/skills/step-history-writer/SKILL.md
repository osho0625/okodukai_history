# Step 履歴書き出し（step-history-writer）

各フェーズスキルの Step 完了時に呼び出される共通スキル。
セッション中の実行履歴を `.aide/tmp/` に書き出す。

## このファイルの目的（最重要・誤解禁止）

このファイルの目的は **「AI がフェーズスキルに記載された工程（前処理・各 Step・後処理・共通スキル呼び出し）を実際に実行した履歴を、そのまま残す」** ことである。

したがって **要約・整形・解釈をしてはならない。** その Step の間に発生した会話履歴（role と発言内容）を、そのまま書き出す。
AI が「何をしたか」をまとめ直すのではなく、実際のやり取り（user / assistant / tool の各メッセージ）をそのまま転記する。
省いてよいのは「コード全文・ファイル全文」など極端に長い本文だけであって、やり取り自体を間引いてはならない。

## 毎Step activate必須・自己流直書き禁止（厳守）

本スキルは、各 Step 完了のたびに必ず activate（`discloseContext` / `Skill` / `activate_skill` 等）して実行すること。以下を厳守する。

- **毎 Step activate 必須:** 前処理・各 Step・後処理それぞれの完了時に、毎回本スキルを activate して履歴を書き出す。前処理で1回 activate したからといって、以降の Step で activate を省略してはならない。activate の目的は「書き方を知ること」ではなく、実行のたびに本スキルの転記ルール（会話履歴をそのまま転記する／要約・捏造禁止／step_id ごと1ファイル）をコンテキストへ再注入することである。
- **自己流 `fs_write` 直書きによる代替の禁止:** 本スキルを activate せずに、AI が記憶を頼りに `fs_write` で「それらしい履歴ファイル」を直接作成することを禁止する。出力先・ファイル名が決め打ち（`.aide/tmp/session-history-{skill_name}-{step_id}.txt`）であるため直書きでも同じ見た目のファイルを作れてしまうが、それは転記ルールが再注入されないまま生成された不正な履歴であり、要約・捏造・束ねの温床となる。
- **step_id ごと1ファイル厳守・束ね禁止:** 履歴ファイルは step_id ごとに必ず1ファイルずつ作成する。複数の Step（例: step1・step2・step3）を `step1-3.txt` のような1ファイルに束ねることを禁止する。1回の activate で書き出すのは、指定された単一の step_id の履歴のみである。
- **承認の転記:** ユーザー承認を履歴に記録するときは、オーケストレータ自身がユーザーと実際に行った対話（確認メッセージとユーザーの応答）をそのまま転記する。サブエージェントの「承認を得た」報告を、オーケストレータが確認していないまま承認として転記してはならない（承認の事実化＝捏造の禁止）。

これらは `.aide/references/phase-skill-rules.md`「全SKILLの activate 必須・独自解釈禁止（最上位原則）」の本スキルにおける個別具体例である。

## 呼び出し元

全7ワークフローの全フェーズスキル（final-check フェーズ含む）から、各 Step 完了時に呼び出される。

## 入力パラメータ

| パラメータ | 型 | 説明 |
|---|---|---|
| skill_name | string | 呼び出し元フェーズスキル名（例: `fs-change-phase1-analysis`） |
| step_id | string | Step 識別子（例: `"前処理"`, `"step1"`, `"step2"` ...） |
| step_title | string | Step のタイトル文字列（例: `"設計書ゲート"`, `"変更要件ヒアリング"` ...） |
| artifact_dir | string | 当該作業の成果物フォルダパス（汎用名）。呼び出し元フェーズスキルが渡す（変更/バグ修正/リファクタリングは `changes_dir` 相当、設計/企画/実装/逆引きは各自の成果物フォルダパス）。プロジェクトルートからの相対パス（例: `.aide/specs/aide-powers/changes/{timestamp}-{name}`）。**渡されなかった場合は `(未指定)` を記録する**（自己導出はしない） |

## 出力ファイル

- パス: `.aide/tmp/session-history-{skill_name}-{step_id}.txt`
- 例: `.aide/tmp/session-history-fs-change-phase1-analysis-step1.txt`
- 例: `.aide/tmp/session-history-fs-bugfix-phase2-impl-前処理.txt`

## Process

### Step 1: 履歴ファイルの書き出し

> **書き込み前チェック（履歴欠落検出・REQ-C-009）:** 下記「**処理:**」の 1 以降（現 Step 履歴の書き込み）へ進む前に、まず本 Step より前に実行されるべき履歴ファイルの欠落を確認する。欠落があればユーザーへ通知し、欠けている先頭の Process からやり直すよう促す。欠落がなければ通常どおり下記の処理へ進む。

**書き込み前チェック手順（履歴欠落検出）:**

A. `skill_name` から当該フェーズスキルの SKILL.md を参照し、その Process 順序（前処理 → Step 1 → Step 2 → …）を取得する。**自己流で順序を推定してはならない**（判定根拠は当該フェーズスキル SKILL.md の Process 順序）。
B. 取得した Process 順序に基づき、「前処理」および現 Step（`step_id`）より前に実行されるべき各 Step について、期待される履歴ファイル `.aide/tmp/session-history-{skill_name}-{当該 step_id}.txt` の一覧を構築する。
C. 一覧の各履歴ファイルが実際に存在するかを確認する。
D. **欠落（歯抜け）がある場合:** ユーザーへ「どの Step／前処理の履歴が欠落しているか」を具体的に通知し、欠けている先頭の Process（前処理、または最初に欠落している Step）からやり直すよう促す。やり直し要否の最終判断や、セッション跨ぎで欠落が説明可能な場合の扱いは、通知を受けたユーザー／オーケストレータが判断する。
E. **欠落がない場合:** 通常どおり下記「**処理:**」へ進み、現 Step の履歴を書き込む（既存の履歴書き込み動作を妨げない）。

**処理:**

1. 出力ファイルパスを構築: `.aide/tmp/session-history-{skill_name}-{step_id}.txt`
2. `.aide/tmp/` ディレクトリが存在しない場合は作成する
3. 以下の内容を Write で書き出す:

```
# Session History: {skill_name} / {step_id}

## メタ情報
- スキル名: {skill_name}
- Step ID: {step_id}
- Step タイトル: {step_title}
- 成果物フォルダパス: {artifact_dir}

## 会話履歴（そのまま転記）

{この Step の間に発生した会話履歴を、role と発言内容のまま順に転記する。}
{各メッセージブロックは role（user / assistant / tool）と本文で構成する。}
{ツール呼び出し（discloseContext / invoke_sub_agent / fs_write 等）は、その引数と結果も tool ブロックとしてそのまま転記する。}
{要約・整形・言い換えをしない。実際のやり取りをそのまま残す。}

[user]
{ユーザーの発言をそのまま}

[assistant]
{AI の応答をそのまま}

[tool] {ツール呼び出し名}
{引数と結果をそのまま}

...（この Step の終わりまで、発生順に転記）
```

**やり取りが長すぎる場合（フォールバック）:**
転記する会話履歴が 200 行以上になる場合は「長すぎる」と判断し、以下に絞ってよい（これら以外は省略可）:
- 方針決定に関連するユーザーとのやり取り（合意・選択・承認・修正指示など）
- プロセス実行が分かる箇所、特に SKILL（discloseContext / Skill 等での activate）とサブエージェント（invoke_sub_agent / Task 等での起動）の実行履歴（引数と結果を含む）

絞る場合も、残す箇所は要約せず role と発言内容のまま転記する。省いた箇所は `（…省略）` と明示する。

4. 書き出し完了を確認する（ファイルが存在すること）

### 記述ルール

- **会話履歴（最重要）**: その Step の間に発生した会話履歴を、role（user / assistant / tool）と発言内容のまま、発生順に転記する。**要約・整形・言い換えは禁止。** ツール呼び出しは引数と結果もそのまま転記する。
  - 含めないのは「コード全文・ファイル全文」など極端に長い本文だけ。その場合は該当箇所を `（…省略: ファイル全文）` のように明示し、やり取り自体は残す。
  - やり取りを間引いたり、AI が「こういう作業をした」とまとめ直すことを禁止する。
  - **やり取りが長すぎる場合のフォールバック**: 転記する会話履歴が 200 行以上になる場合は「長すぎる」と判断し、(1) 方針決定に関連するユーザーとのやり取り、(2) プロセス実行が分かる箇所（特に SKILL・サブエージェントの実行履歴）に絞ってよい。それ以外は省略可。ただし残す箇所は要約せず role と発言内容のまま転記し、省いた箇所は `（…省略）` と明示する。

### エラー時の動作

- `.aide/tmp/` への書き込みに失敗した場合: ユーザーに報告し、手動での対処を依頼する。フェーズスキルの実行は中断しない（履歴書き出し失敗はフェーズ中断の理由にならない）
- ただし、final-check フェーズで履歴ファイルが欠落している場合は検証 FAIL の原因となる

## Integration

**Called by:**
- 全7ワークフローの全フェーズスキル（各 Step 完了時）

**Used by:**
- `progress-final-checker (aide-powers agent)` — final-check フェーズで参照可能（進捗完了確認の補助情報）

**依存スキル:** なし（単独で動作する最小スキル）
