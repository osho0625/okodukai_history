# Spec Reviewer Prompt Template

design-review-agent（agents/ 配下の名前付きエージェント）を呼び出す際のプロンプト構築テンプレート。
2つのモード（implementation, test）に対応する。

---

## mode: implementation（実装コードレビュー）

### 使い方

design-review-agent を mode: implementation で呼び出す際に、以下のテンプレートの `{変数}` を埋めて Task でディスパッチする。

### テンプレート

```
### レビューモード
implementation

### 対象ファイル
- {src/レイヤー/ファイル名.py}

### 設計書（照合元）
- {設計書ファイルパス} → セクション: {該当クラス名}
- {プログラム構成書ファイルパス} → セクション: importルール

### 設計書全項目チェック（必須）
設計書の該当セクションに記載されている**すべての項目**（クラス定義、メソッドシグネチャ、不変条件、Raises、テスト観点等）について、実装コードで対応されているかを1項目ずつ確認すること。
確認結果をレビュー出力に以下の形式で含めること:
- ✅ {項目名}: 実装済み
- ❌ {項目名}: 未実装（理由: {理由}）
1つでも ❌ がある場合は FAIL とする。

## CRITICAL: Do Not Trust the Report
実装者の報告を信用しない。設計書と実装コードを自分の目で照合すること。

## レビュー観点
1. **内部ロジック意図検証（最優先）**: メソッドの処理内容が設計書の意図・目的を満たしているか
2. **クラス存在チェック**: 設計書に定義された全クラスが存在するか
3. **メソッドシグネチャチェック**: 全パブリックメソッドの名前・引数・戻り値が設計書と一致するか
4. **コンストラクタチェック**: __init__ の引数、DI対象の依存が設計書通りか
5. **処理フローチェック**: 設計書に記載された処理フローに従っているか
6. **不変条件チェック**: 値オブジェクトの不変条件が設計書通りか
7. **過去不具合修正の保持検証**: bugfix/ 配下の修正が保持されているか（目視確認必須）
8. **設計書にないものの検出**: 未定義のパブリックメソッド/属性が追加されていないか
9. **importルールチェック**: アーキテクチャの依存ルールに違反していないか

## 乖離種別判定ルール
差分を検出した場合、以下の二択で判定する:
- **FAIL_IMPL（実装誤り）**: 設計書が正しく、実装が設計に準拠していない → fix で実装を修正
- **FAIL_DESIGN（設計漏れ）**: 実装が正しく、設計書が実態を反映していない → design-sync で設計書を更新
importルール違反は設計漏れ判定の対象外（常に FAIL_IMPL として実装修正が必要）。

## 報告フォーマット
- 設計準拠: PASS / FAIL（差分N件。各差分に FAIL_IMPL / FAIL_DESIGN を付記）
- importルール: PASS / FAIL（違反N件）
- 差分詳細（FAILの場合）
- サマリ
```

## mode: test（テストコードレビュー）

### 使い方

design-review-agent を mode: test で呼び出す際に、以下のテンプレートの `{変数}` を埋めて Task でディスパッチする。

### テンプレート

```
### レビューモード
test

### 対象ファイル
- {tests/レイヤー/test_ファイル名.py}

### 設計書（照合元）
- {設計書ファイルパス} → セクション: {該当クラス名}（テスト観点）

### 実装ファイル（テスト対象）
- {src/レイヤー/ファイル名.py}

## レビュー観点
1. **パブリックメソッドのテスト必須**: 全パブリックメソッドに対応するテストが存在するか
2. **テストケース網羅性**: 設計書の「テスト観点」の全ケースに対応するテストメソッドが存在するか
3. **境界値テスト**: 設計書の不変条件に対して境界値テストがあるか
4. **異常系テスト**: 設計書の「Raises」セクションの全例外に対するテストがあるか
5. **importルールチェック**: テストファイルのimportが適切か

## 判定基準
カバー率100% → PASS、100%未満 → FAIL

## 報告フォーマット
- テスト網羅性（設計観点）: PASS / FAIL（未カバーN件）
- カバレッジサマリ
- 未カバー項目の詳細（FAILの場合）
```
