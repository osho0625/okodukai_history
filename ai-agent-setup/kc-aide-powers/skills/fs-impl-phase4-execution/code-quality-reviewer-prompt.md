# Code Quality Reviewer Prompt Template

code-review-agent（agents/ 配下の名前付きエージェント）を呼び出す際のプロンプト構築テンプレート。
2つのモード（implementation, test）に対応する。

---

## mode: implementation（実装コードレビュー）

### 使い方

code-review-agent を mode: implementation で呼び出す際に、以下のテンプレートの `{変数}` を埋めて Task でディスパッチする。

### テンプレート

```
### レビューモード
implementation

### 対象ファイル
- {src/レイヤー/ファイル名.py}

### 設計書（Raisesセクション参照用）
- {設計書ファイルパス} → セクション: {該当クラス名}

## CRITICAL: Do Not Trust the Report
実装者の報告を信用しない。コードを自分の目で確認すること。

## レビュー観点（コード品質）
1. **命名規約**: プロジェクトのコーディング規約に準拠しているか
2. **ファイルサイズ**: 1ファイル200行以下（超過はWARNING）
3. **1ファイル1クラス原則**: 例外ファイル以外で複数クラスが定義されていないか
4. **型ヒント**: 全パブリックメソッドの引数・戻り値に型ヒントがあるか
5. **docstring**: 全パブリックメソッド・全クラスにdocstringがあるか
6. **コメント品質**: コード翻訳コメント禁止、変更経緯コメント禁止、コメントアウトコード禁止
7. **SOLID原則**: SRP, OCP, LSP, ISP, DIP の各原則に違反していないか
8. **その他品質**: マジックナンバー、過度なネスト、未使用import
9. **if/elif/else網羅性**: 最後の条件を else で暗黙処理していないか
10. **過去不具合再発チェック**: bugfix/ 配下の修正が保持されているか（目視確認必須）
11. **ダミー実装の検出**: pass のみ、NotImplementedError、ハードコード固定値、TODO付き仮実装
12. **デッドコードの排除**: 未参照メソッド・属性・変数

## レビュー観点（エラーハンドリング）
1. **レイヤー間の例外変換ルール**: インフラ→アプリケーション: ラップ必須
2. **例外ラップの正確性**: cause 属性に元の例外が設定されているか
3. **Raises仕様チェック**: 設計書のRaisesセクションと実装の一致
4. **try/exceptの適切性**: エラーもみ消し防止、例外チェイン、bare except禁止
5. **ログ出力**: 適切なログレベル、二重計上防止
6. **エラーメッセージ品質**: 具体性、機密情報の排除

## 判定基準
- ERROR 0件 → PASS、1件以上 → FAIL
- WARNING, INFO は PASS/FAIL に影響しない

## 報告フォーマット
- コード品質: PASS / FAIL（ERROR N件, WARNING N件）
- エラーハンドリング: PASS / FAIL（ERROR N件）
- 詳細（FAILの場合）
- サマリ
```

## mode: test（テストコードレビュー）

### 使い方

code-review-agent を mode: test で呼び出す際に、以下のテンプレートの `{変数}` を埋めて Task でディスパッチする。

### テンプレート

```
### レビューモード
test

### 対象ファイル
- {tests/レイヤー/test_ファイル名.py}

## レビュー観点
0. **パブリックメソッドのテスト必須**: 全てのパブリックメソッドに対応するユニットテストが存在すること。設計書の「テスト観点」に記載がないパブリックメソッドであっても、テストは必須
1. **テスト命名規則**: ファイル名: test_{対象}.py、クラス名: Test{対象}、メソッド名: test_{メソッド}_{条件}_{期待結果}
2. **テスト独立性**: 各テストが独立実行可能か、テスト間依存がないか
3. **モック・スタブ使用禁止**: unittest.mock のimportがあれば即ERROR
4. **境界値テスト**: 境界値テストが含まれているか
5. **異常系テスト**: assertRaises が含まれているか

## 判定基準
違反0件 → PASS、1件以上 → FAIL

## 報告フォーマット
- テスト方針準拠: PASS / FAIL
- 違反詳細（FAILの場合）
- サマリ
```
