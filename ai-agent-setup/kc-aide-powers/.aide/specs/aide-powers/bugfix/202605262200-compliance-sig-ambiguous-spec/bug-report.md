# バグ報告

## 報告日
2026-05-26

## バグの症状
phase-compliance-check スキルの verify モードで、署名対象文字列の第4引数に何を渡すかが曖昧。スキルには「成果物一覧のSHA256」と書いてあるが、実際のスクリプト (compliance-sig) は artifact-hash サブコマンドで二重ハッシュ（成果物SHA256値をさらにSHA256）した値を使用する。この仕様差により、AIエージェントが手動で署名対象文字列を構築して検証しようとすると「署名不一致」になる。

## 再現手順
1. phase-compliance-check スキルの verify モードを実行する
2. スキルの記述に従い「成果物一覧のSHA256」を第4引数として署名対象文字列を手動構築する
3. compliance-sig スクリプトの verify サブコマンドで検証する
4. 署名不一致エラーが発生する

## 期待動作
スキルの記述通りに署名対象文字列を構築すれば、署名検証が成功すること。
または、スキルに「verify時はスクリプトの verify サブコマンドに全て任せよ。手動で署名対象文字列を構築して比較するな」と明記されていること。

## 実際の動作
スキルの記述に従って手動で署名対象文字列を構築すると、compliance-sig スクリプトが内部で使用する artifact-hash サブコマンドの二重ハッシュ値と一致せず、「署名不一致」エラーになる。

## 発生頻度
毎回（verify モードで手動構築を試みるたびに発生）

## 発生環境・条件
- phase-compliance-check スキルの verify モード実行時
- AIエージェントがスキルの記述を読んで手動で署名対象文字列を構築しようとした場合

## 補足情報
- 発見元: 変更WF (202605262130-add-progress-final-check)
- compliance-sig スクリプトの artifact-hash サブコマンドは、成果物SHA256値をさらにSHA256する（二重ハッシュ）
- スキルの記述と実際のスクリプト動作に乖離がある
- 修正方針として3点が提案されている:
  1. phase-compliance-check スキルに「verify時はスクリプトの verify サブコマンドに全て任せよ」と明記
  2. 署名対象文字列の第4引数は artifact-hash サブコマンドの出力値であることを明記
  3. compliance-checker agent の定義にも同様の注意書きを追加
