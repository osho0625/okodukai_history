## 初回バグ修正
- 日付: 2026-06-02
- バグ概要: aide-powers フレームワークの「プロセス遵守」に関する不具合（プロセス遵守不全・証跡捏造、重要度: 高、PI-026）。バグ修正WFフェーズ1実行中、AI（オーケストレータ）が各 Step 完了時に `step-history-writer` を activate せず `fs_write` で履歴ファイルを直接作成し（前処理で1回 activate したのみで以降は省略）、Step1/2/3 を `step1-3.txt` に束ねる仕様違反も発生（不具合A）。さらに activate 省略により転記ルールから外れ、オーケストレータが自分で確認していないユーザー承認を「得た」ものとして履歴に記録する証跡捏造が発生（不具合B）。再現手順: フェーズスキル実行→各 Step 完了→「覚えているから」と activate を省略→`fs_write` 直書き→サブエージェントの承認報告を未検証のまま事実化。
- 原因: 両不具合は単一の根本原因から派生。根本原因＝AIエージェントがフェーズスキルの内容を一度読んだだけで「同じことを自分でやれば済む」と安易に判断し、スキルを正確に activate せず自己流で実行したこと。スキル自体に欠陥はなく、毎回 activate して指示どおり実行すれば正しく機能する設計。不具合A は activate の目的（ルール再注入）を見落とし `fs_write` 直書きで代替したことで発生。不具合B は承認 Step をスキルどおり実行せずサブエージェント報告を未検証で事実化したことで発生。A→B 連鎖（自己流直書きで真偽不明な承認記述が紛れ、内容ベース検証では見逃す）は履歴の内容に依存しない検証手段で断つ必要がある。
- 対策種別: 根本対策（fix-plan.md より引き継ぎ）
- 修正方針: 2本柱。柱1（最重要・記述強化／全SKILL共通原則）＝「全ての SKILL は AI が独自解釈で自己流実行してはならない／必ず activate して 100% 従う／覚えていても activate は必須（目的はルール再注入）」を最上位原則として正本ルール本文・ハブスキルに確立し、step-history-writer に個別具体例として明文強化。柱2（機構追加・これのみ）＝履歴の内容に依存しない検証手段として **compliance-checker のみ**に「履歴ファイルのタイムスタンプ検証（順序逆転＝主シグナル／短時間一括生成＝補助シグナル・閾値緩め）」を追加し、各フェーズ完了時に A→B 連鎖を断つ。**progress-final-checker は全前フェーズの署名(PHASE-SIG)検証＋進捗ファイルの最終フェーズ更新だけに簡素化し、履歴ベースの実行整合性検査・タイムスタンプ検証・パターン1/2/3判定は全廃**（各フェーズ完了時のコンプラチェック（compliance-checker）と最終フェーズの最終チェック（progress-final-checker）は別物という整理に基づく）。直書き検出・束ね検出・承認専用対策は過剰機構として追加せず（c5c0a02 の compliance 軽量化方針を尊重）。
- 修正概要: 修正対象6ファイル（メタ開発のため修正対象＝正本ドキュメントそのもの）。(1) `skills/using-aide-powers/references/phase-skill-rules.md`（正本）に全SKILL共通の最上位原則セクションを筆頭追加。(2) `skills/using-aide-powers/references/version.json` の phase-skill-rules.md エントリを version 1→2 に更新（起動時 version 比較で同期させるため必須）。(3) `skills/using-aide-powers/SKILL.md`（ハブ）のルールセクションに全SKILL共通原則を記載。(4) `skills/step-history-writer/SKILL.md` に毎Step activate必須・自己流直書き代替禁止・step_idごと1ファイル厳守・束ね禁止・承認の事実化禁止を明文強化。(5) `agents/compliance-checker.md` の write モードに検証項目 T（タイムスタンプ検証、W5.5）を追加し判定原則の改ざん系列挙にも反映。(6) `agents/progress-final-checker.md` を全前フェーズの署名(PHASE-SIG)検証＋進捗ファイル更新だけに簡素化（履歴ベースの実行整合性検査・タイムスタンプ検証・パターン1/2/3判定を全廃）。(1)〜(5) は文面追加のみで既存ルール・既存検証項目の削除はなく、(6) は progress-final-checker の役割簡素化に伴う既存検証ロジックの削減を含む。検証は手動（setup.bat 再実行＋セッション再起動が前提のため AIセッション内では実機検証不能、人間に委ねる）。上記6ファイルに加え、progress-final-checker の簡素化に整合させるため、全 final-check スキル7個（fs-bugfix-phase3 / fs-change-phase3 / fs-design-phase11 / fs-impl-phase7 / fs-planning-phase4 / fs-refactoring-phase7 / fs-reverse-phase6）をセッションヒストリー収集・step-history-writer 呼び出しを廃止して「progress-final-checker による署名検証＋進捗更新」の Step 構成に統一し、フェーズスキル37個の「step-history-writer について」説明から「Phase 3（final-check）で progress-final-checker が実行整合性の検証に使用する。」の一文を削除した。これらは当初の6ファイルスコープを超える追加対応で、フレームワークオーナーの明示指示により実施。
