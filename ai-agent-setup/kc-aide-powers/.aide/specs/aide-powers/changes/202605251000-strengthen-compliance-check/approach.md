## 変更方針の詳細

### 1. write モード入力パラメータ追加（REQ-C-001）

| 新パラメータ | 型 | 説明 |
|---|---|---|
| process_full_text | 文字列 | 該当フェーズスキルの SKILL.md の Process セクション全文（前処理・Step群・後処理すべて） |
| execution_evidence | 文字列 | オーケストレータが会話履歴から切り出した実行証跡（各ステップの実行を証明できる箇所の抜粋） |

**理由:** 自己申告だけでは虚偽宣言を防げない。Process 全文と証跡を第三者（compliance-checker）に渡して照合させることで、客観的な検証を実現する。

### 2. 新検証項目 I: Process実行証跡照合（REQ-C-001）

- compliance-checker が Process の各ステップ（前処理・Step・後処理）を1件ずつ列挙する
- 各ステップに対応する証跡が execution_evidence 内に存在するか照合する
- 証跡なしのステップがある場合 → FAIL（理由: 「Step X の実行証跡が不足」）

### 3. 新検証項目 J: サブエージェント委譲検証（REQ-C-002）

- Process 全文から「Task でサブエージェントをディスパッチする」「サブエージェントに委譲する」等のキーワードを検出する
- 該当箇所ごとに、証跡にサブエージェント呼び出し（invoke_sub_agent 等）の記録があるか確認する
- オーケストレータ自身が実行した証跡しかない場合 → FAIL（理由: 「Step X でサブエージェント委譲が指示されているが、オーケストレータが自己実行している」）

### 4. 成果物なしフェーズの署名手順明確化（REQ-C-003）

- 署名対象文字列: `{workflow}|{phase}|{datetime}|{SHA256_OF_EMPTY_STRING}`
- SHA256_OF_EMPTY_STRING = `E3B0C44298FC1C149AFBF4C8996FB92427AE41E4649B934CA495991B7852B855`
- この値は「成果物テーブルに SHA256 列の値が0件」の場合に使用する
- 明文化場所: phase-compliance-check/SKILL.md と agents/compliance-checker.md の両方
