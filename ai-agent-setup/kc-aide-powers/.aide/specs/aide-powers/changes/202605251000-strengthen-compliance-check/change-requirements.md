# 変更要求定義: phase-compliance-check 検証項目強化

## 変更概要

### 目的・背景

フェーズ完了時の compliance-check (write) において、AI エージェントが虚偽の自己申告（全ステップ実行済みと宣言しながら実際には省略）を行う問題が発生した（PENDING-031）。また、フェーズスキルでサブエージェント委譲が指示されている処理をオーケストレータが自己実行するケースも発生している。

現状の compliance-check は自己申告ベースであり、客観的な証跡検証が不足している。

### 変更種別

仕様変更（modification）

---

## 要求事項

### REQ-C-001: Process実行証跡の客観的検証

- **種別:** 仕様変更
- **説明:** compliance-check (write) 実行時に、compliance-checker サブエージェントに以下の2つを渡し、照合検証を行う:
  1. 該当フェーズスキルの SKILL.md の Process セクション全文（前処理・Step群・後処理すべて）
  2. オーケストレータが会話履歴から切り出した「実行証跡」（各ステップの実行を証明できる箇所の抜粋）
- **受入基準:**
  - compliance-checker が Process の各ステップに対応する証跡の有無を1件ずつ照合する
  - 証跡が存在しないステップがある場合、FAIL を返す
  - 証跡の形式は自由テキスト（オーケストレータが「これで証明できる」と判断した箇所の切り出し）
- **優先度:** Must

### REQ-C-002: サブエージェント委譲指示の無視検出

- **種別:** 仕様変更
- **説明:** Process 内で「Task でサブエージェントをディスパッチする」「サブエージェントに委譲する」等の記述がある箇所について、証跡にサブエージェント呼び出し（invoke_sub_agent 等）の記録があるかを検証する。オーケストレータが自己実行している場合は FAIL とする。
- **受入基準:**
  - SKILL.md の Process から「サブエージェント委譲」指示箇所を抽出する
  - 各委譲指示に対応するサブエージェント呼び出しの証跡があるか確認する
  - 委譲指示があるのにオーケストレータ自身が実行した証跡しかない場合、FAIL を返す
  - FAIL 時の理由に「どのステップで委譲違反が検出されたか」を明記する
- **優先度:** Must

### REQ-C-003: 成果物なし時の署名手順の明確化

- **種別:** 仕様変更
- **説明:** フェーズ1（状態確認）等、成果物を作成しないフェーズにおける署名対象文字列の構築方法と手順を明確に定義する。現状は成果物ハッシュが空文字列のSHA256（E3B0C44298FC...）で代用されているが、これが正式な仕様として明文化されていない。
- **受入基準:**
  - phase-compliance-check スキルに「成果物なしフェーズの署名手順」セクションを追加する
  - 署名対象文字列の構築ルールを明記する（例: `{workflow}|{phase}|{datetime}|{SHA256_OF_EMPTY_STRING}`）
  - compliance-checker エージェント定義にも同ルールを反映する
  - 成果物なしフェーズでも verify モードで署名検証が正常に動作する
- **優先度:** Must

## 対象外（スコープ外）

- フェーズスキル（fs-*）自体の Process 記述の変更
- 進捗ファイルフォーマット（progress-file-format.md）の変更
- 全フェーズスキルへの後処理テンプレート変更の反映（本変更で定義を確定し、反映は別ワークフローで実施）

## 前提条件

- phase-compliance-check/SKILL.md が変更対象として存在する
- agents/compliance-checker.md が変更対象として存在する
- オーケストレータは会話履歴にアクセスでき、証跡を切り出す能力がある
