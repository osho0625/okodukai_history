- 「進捗ファイル更新フォーマット」セクション内の省略なし宣言コメント行・署名行の記述

### 3.9 FAIL 時のユーザー通知（簡素化）

**After:** 成果物欠落・前フェーズ未完了の2パターンのみ。通知テンプレートを以下に簡素化:

```markdown
⚠️ **進捗更新 FAIL**

**ユーザーへの確認（必須）:**
1. やり直す（該当フェーズを再実行する）
2. このまま進める（問題を認識した上で完了とする）

```

**変更理由**: 署名関連の FAIL パターンが消えるため、通知テンプレートを簡素化

### 4.3 検証手順 B — 全前フェーズの検証

**Before:**
```markdown
### B. 全前フェーズの署名検証

1. **署名項目の存在確認**
   - 各前フェーズ N に `<!-- PHASE-SIG:{N}:{SHA256} -->` 署名行が存在するか
   - 各前フェーズ N に `<!-- COMPLIANCE-DECLARATION:{N}: ... -->` 宣言行が存在するか
   - いずれかが1つでも存在しないフェーズがある場合 → FAIL
   - ただし N が `skipped_phases` に含まれる場合はこの確認をスキップする

2. **署名の再計算と照合**
   - `bash .aide/scripts/create-sig.sh` で各前フェーズの署名を再計算し、記録値と一致するか検証する
   - 1つでも不一致 → FAIL
   - N が `skipped_phases` に含まれる場合は対象外

3. **ステータステーブルの完了確認**
   - 全前フェーズ（自フェーズ除く）が ✅ 完了 になっているか

   - N が `skipped_phases` に含まれる場合は ✅完了 を要求しない
```

**After:**
```markdown
### B. 全前フェーズの完了確認

最終フェーズ（自フェーズ）を除く全前フェーズ（1 〜 total_phases）について、以下を検証する。

> **skipped_phases による除外:** `skipped_phases` に含まれるフェーズ番号は ⏭️ スキップ（許容）として扱い、✅完了 を要求せず FAIL 対象としない。

1. **ステータステーブルの完了確認**

   - N が `skipped_phases` に含まれる場合は ✅完了 を要求せず、⏭️ スキップ（許容）として FAIL 対象としない
```
