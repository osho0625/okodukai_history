# 変更要求定義

## 変更概要
- **変更の目的・背景**: aide agent 対応の commit によりプロセス省略問題が解決する傾向にあるため、各フェーズスキルの前処理・後処理で実施していた署名検証（SHA256）およびレポート記載項目検証を削除し、軽量な「進捗確認・進捗更新」に置き換える。進捗チェック自体はサブエージェントとして残し、進捗ファイルの読み込み・書き込みを引き続き担当させる。
- **変更種別**: 変更

## 要求事項

### REQ-C-001: フェーズ前処理の署名検証削除と進捗確認への置換
- **種別**: 変更
- **説明**: 各フェーズスキル（fs-*）の前処理で実施している署名検証（直前フェーズの SHA256 署名検証）を削除し、`progress-resume-check` の結果に基づく進捗確認のみに変更する。前処理ではサブエージェントが進捗ファイルを読み込み、現在のフェーズ番号と照合して再開判定を行うだけとする。
- **受入基準**:
  - AC-001: 各フェーズスキルの前処理で SHA256 署名検証が実行されないこと
  - AC-002: 各フェーズスキルの前処理で `progress-resume-check` による進捗確認が引き続き実行されること
  - AC-003: 署名検証の失敗によるフェーズブロックが発生しなくなること
- **優先度**: 必須

### REQ-C-002: フェーズ後処理のレポート確認削除と進捗更新への置換
- **種別**: 変更
- **説明**: 各フェーズスキル（fs-*）の後処理で実施しているレポート記載項目漏れ検証および SHA256 署名生成を削除し、単純な進捗ファイル更新のみに変更する。サブエージェントが進捗ファイルへの完了記録書き込みを引き続き担当する。
- **受入基準**:
  - AC-004: 各フェーズスキルの後処理でレポート記載項目の漏れ検証が実行されないこと
  - AC-005: 各フェーズスキルの後処理で進捗ファイル（progress file）の更新が引き続きサブエージェントにより行われること
  - AC-006: SHA256 署名の生成が実行されなくなること
  - AC-007: 省略なし宣言・署名行の埋め込みが行われなくなること
- **優先度**: 必須

### REQ-C-003: 最終フェーズの全署名検証削除
- **種別**: 変更
- **説明**: 各ワークフローの最終フェーズ（fs-*-phase*-final-check）で実施している全前フェーズの署名検証を削除する。最終フェーズでは進捗ファイルの全フェーズ完了確認のみを行い、署名の整合性チェックは行わない。
- **受入基準**:
  - AC-008: 最終フェーズで全フェーズの署名検証が実行されなくなること
  - AC-009: 最終フェーズでの進捗ファイルに基づく完了確認は引き続き行われること
- **優先度**: 必須

### REQ-C-004: phase-report-check スキルの簡素化
- **種別**: 変更
- **説明**: `phase-report-check` スキルから署名検証・レポート記載項目検証の機能を削除し、進捗更新・進捗確認の機能のみを残す。前処理（verify）は「進捗確認」に名称変更し、サブエージェントで進捗ファイルを読み再開判定を行う。後処理（write）は「進捗更新」に名称変更し、サブエージェントで進捗ファイルに完了記録を書き込む。
- **受入基準**:
  - AC-010: `phase-report-check` スキルから署名検証ロジックが除去されていること
  - AC-011: `phase-report-check` スキルからレポート記載項目検証ロジックが除去されていること
  - AC-012: 前処理（旧 verify）がサブエージェントとして進捗確認を実行すること
  - AC-013: 後処理（旧 write）がサブエージェントとして進捗更新を実行すること
  - AC-014: 署名生成・省略なし宣言の埋め込みが行われないこと
- **優先度**: 必須

### REQ-C-005: phase-report-checker エージェントの簡素化
- **種別**: 変更
- **説明**: `phase-report-checker` エージェントから署名生成・署名検証・レポート記載項目検証の機能を削除し、進捗ファイル更新のみを担当するエージェントに変更する。エージェントの役割が「レポートチェック」から「進捗ファイル更新」に変わるため、名称変更（例: `progress-updater` 等）も検討する。
- **受入基準**:
  - AC-015: `phase-report-checker` エージェントから署名生成・検証ロジックが除去されていること
  - AC-016: `phase-report-checker` エージェントからレポート記載項目検証ロジックが除去されていること
  - AC-017: エージェントが進捗ファイルの読み込み・書き込みを引き続き担当すること
  - AC-018: エージェント名称が役割に合った名前に変更されていること（または変更理由が記録されていること）
- **優先度**: 必須

### REQ-C-006: phase-compliance-check スキルおよび compliance-checker エージェントの削除
- **種別**: 変更
- **説明**: `phase-compliance-check` スキルおよび `compliance-checker` エージェントを削除する。これらは署名検証を主目的としたフェーズ遵守チェック機構であったが、署名検証廃止に伴い不要となる。進捗確認・進捗更新の機能は `phase-report-check` スキル（簡素化後）に統合済みであるため、別途存在する必要がない。
- **受入基準**:
  - AC-019: `phase-compliance-check` スキルが呼び出し可能な状態でなくなること（削除）
  - AC-020: `compliance-checker` エージェントが呼び出し可能な状態でなくなること（削除）
  - AC-021: 他のスキル・エージェントから `phase-compliance-check` および `compliance-checker` への参照が除去されていること
- **優先度**: 必須

## 対象外（スコープ外）
- `progress-resume-check` スキルの変更（このスキルは現状のまま残す）
- `step-history-writer` スキルの変更（このスキルは現状のまま残す）
- 進捗ファイル（progress file）のフォーマット変更（署名フィールドが不要になるが、フォーマット変更は影響分析フェーズで判断する）
- フェーズレポートの内容・構成の変更（レポート自体は引き続き記載する。検証を削除するのみ）

## 前提条件
- aide agent の対応が既に commit 済みであり、プロセス省略問題が解決傾向にあること
- 署名検証がなくてもフェーズの省略を検知・防止できる代替機構（aide agent による制御）が機能していること
- 進捗チェック（進捗ファイルの読み書き）はサブエージェントとして残す方針が確定していること
