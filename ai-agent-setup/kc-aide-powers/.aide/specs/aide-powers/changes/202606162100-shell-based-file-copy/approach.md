## 変更方針の詳細

### 1. using-aide-powers: references コピーのシェルコマンド化

- **方針**: 起動手順2の「version 不一致時にコピーする」手順記述を、Read→Write 方式からシェルコマンド（`Copy-Item` / `cp`）方式に書き換える。version.json の比較ロジック（Read で読んで比較）は現行維持。コピー実行部分のみシェルコマンド化する。
- **理由**: 
  - 10ファイルの全文をAIコンテキストに展開する必要がなくなり、コンテキスト消費をほぼゼロにできる
  - AIが1ファイルずつ Read → Write する数ターンの処理が、1回のシェルコマンド実行で完結する
  - スキルの手順記述が「Read → Write でコピー」と指示している限りAIはその方式で動くため、手順記述自体の変更が必須

- **変更箇所の詳細**:
  - 現行の手順2で「正本からごっそり置き換える」部分の記述を、OS判定付きシェルコマンドに置き換える
  - Windows: `Copy-Item -Path "正本パス/*" -Destination ".aide/references/" -Recurse -Force`
  - Linux/Mac: `cp -r 正本パス/* .aide/references/`
  - `.aide/references/` ディレクトリが存在しない場合の mkdir も含める
  - `.rules-updated` フラグファイル作成もシェルコマンドで実行（`New-Item` / `touch`）

- **維持する部分**:
  - version.json の Read と比較ロジック（小さいJSONファイルの読み込みのため問題なし）
  - version 一致時に何もしない動作
  - フラグファイルの役割とプロトコル

### 2. rules-distribute: global モードのシェルコマンド化

- **方針**: ステップ2の「ソースファイルを Read で全文読み込み → front-matter + マーカー + 本文を組み立てて Write」の手順記述を、シェルコマンドによる文字列結合 + ファイル書き込み方式に書き換える。
- **理由**:
  - global-rules.md / phase-skill-rules.md は数百行規模のファイルであり、全文をAIコンテキストに展開して書き写す現行方式はコンテキスト消費が大きい
  - front-matter テンプレートは固定文字列のため、シェルコマンドで機械的に結合可能
  - 生成方法が変わるだけで出力ファイルの内容・配置先・命名は不変のため、下流への影響なし

- **変更箇所の詳細**:
  - 「入力ソース」セクションの「両ファイルを Read ツールで全文読み込み」の記述を削除し、シェルコマンドで直接結合する方式に変更
  - 「差分検知＆置き換え処理」セクションの手順3で、Write ツールの代わりにシェルコマンドを使用する記述に変更
  - 各プラットフォームのフォーマット記述はそのまま維持するが、「出力方法」をシェルコマンド例に置き換える
  - front-matter テンプレート文字列 + ソースファイル内容の結合コマンドを明示
  - front-matter なしプラットフォーム（Codex / OpenCode / Gemini）は単純コピー（`Copy-Item` / `cp`）で対応
  - 配置先ディレクトリの自動作成もシェルコマンドで実施（`New-Item -ItemType Directory -Force` / `mkdir -p`）

- **維持する部分**:
  - `.rules-updated` フラグの確認・削除ロジック
  - 配置先ファイルが存在しない場合の初回配置保証
  - フラグなし＆配置先存在時のスキップ動作
  - `AGENTS.md` / `GEMINI.md` への参照行追記ロジック（1行の追記のみのため現行通りAIが実行）
  - skill モード（deploy / cleanup）の記述は一切変更しない

### 3. クロスプラットフォーム対応の記述方針

- **方針**: SKILL.md 内でシェルコマンドを記述する際、Windows（PowerShell）と Linux/Mac（bash）の両方のコマンド例を併記する。AIがOS判定を行い、適切なコマンドを選択して実行する。
- **理由**:
  - dev-environment.md §4 で「2系統維持」が明記されている
  - 変更要求の前提条件で「スキル記述はクロスプラットフォーム対応」と指定されている
  - AIは実行環境のOSを判定可能（PWD パス形式、`$env:OS` 等）

- **検討結果**: 不要
- **理由**: 
  - 変更は2つの SKILL.md の手順記述の部分的書き換えのみで完結する
