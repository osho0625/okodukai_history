# 変更要求定義

## 変更概要
- **変更の目的・背景**: 実装を伴う全ワークフロー（実装WF / 変更WF / bugfix WF）の動作確認ステップにおいて、現状は build/テスト通過後にユーザーへ動作検証を依頼するだけの構成になっている。しかし、build が通るだけでは実際の動作が正しいことの保証にならず、動作検証が不十分なまま完了扱いになるケースが発生している。FS（フェーズスキル）がプロンプトテンプレートを用意してサブエージェントを起動し、サブエージェントが動作確認試験を実行する仕組みを全WF横断で導入することで、動作確認の品質を向上させる。
- **変更種別**: 仕様変更
- **対象WF・対象ステップ**:
  - 実装WF: fs-impl-phase4-execution（実装ループ完了後の動作確認）
  - 変更WF: fs-change-phase2-impl の Step12
  - bugfix WF: fs-bugfix-phase2-impl の Step10（※既にコミット 8509340 で適用済み。要件としては含める）

## 要求事項

### REQ-C-001: サブエージェントによる動作確認の必須化（全WF共通）
- **種別**: 変更
- **説明**: 実装を伴う全WF（実装WF / 変更WF / bugfix WF）の動作確認ステップにおいて、FSがサブエージェントを起動して動作確認試験を実行させることを必須とする。FSの責務はプロンプトテンプレートの準備とサブエージェントの起動であり、FS自身が直接試験を実行するのではない。動作確認とは、実際にアプリケーションを動作させ、WF種別に応じた試験項目を検証することを意味する。build が通る・単体テストが通るだけでは動作確認とみなさない。
- **受入基準**:
  - AC-001: 各WFの動作確認ステップに「FSがサブエージェントを起動して動作確認試験を実行させる」手順が定義されていること
  - AC-002: FSの責務が「プロンプトテンプレート準備 → サブエージェント起動 → 結果受領」に限定されていることが明記されていること
  - AC-003: 「動作確認」の定義として「build/テスト通過だけでは不可」が明記されていること
- **優先度**: 必須

### REQ-C-002: 動作確認プロンプトテンプレートの作成（サブエージェント委譲）
- **種別**: 変更
- **説明**: FSがサブエージェントに動作確認を委譲するためのプロンプトテンプレートを作成する。テンプレートにはWF種別に応じた試験項目、試験対象、試験手順の雛形を含める。FSはこのテンプレートに具体的な情報（対象ファイル、変更内容、受入基準等）を埋め込んでサブエージェントを起動する。
- **受入基準**:
  - AC-004: プロンプトテンプレートがWF種別ごと（実装WF / 変更WF / bugfix WF）に定義されていること
  - AC-005: テンプレートに「試験項目」「試験対象」「試験手順の雛形」「結果報告フォーマット」「試験書出力の指示」が含まれること
  - AC-006: FSがテンプレートに具体情報を埋め込んでサブエージェントを起動する手順が定義されていること
- **優先度**: 必須

### REQ-C-003: WF種別に応じた試験内容の定義
- **種別**: 変更
- **説明**: WF種別ごとに動作確認試験の内容を定義する。各WFの目的に応じて適切な試験観点を設定する。
  - **変更WF**: 受入基準（AC-xxx）ベースの受入判定試験 + 対処内容ベースの動作試験
  - **bugfix WF**: 受入基準（AC-xxx）ベースの受入判定試験 + 不具合対処内容ベースの動作試験
  - **実装WF**: ユースケースベースの試験 + 動作試験書（manual-test-plan.md）ベースの試験
- **受入基準**:
  - AC-007: 変更WFの試験内容として「受入基準ベースの受入判定試験」と「対処内容ベースの動作試験」が定義されていること
  - AC-008: bugfix WFの試験内容として「受入基準ベースの受入判定試験」と「不具合対処内容ベースの動作試験」が定義されていること
  - AC-009: 実装WFの試験内容として「ユースケースベースの試験」と「動作試験書ベースの試験」が定義されていること
  - AC-010: 各WFの試験内容がプロンプトテンプレート（REQ-C-002）に反映されていること
- **優先度**: 必須

### REQ-C-004: ローカル/試験環境での実行制約
- **種別**: 変更
- **説明**: 動作確認はローカル環境または試験環境で実行し、運用中のシステムに影響を与えないことを制約として明記する。
- **受入基準**:
  - AC-011: ローカル/試験環境で実行する旨が各WFの動作確認手順に明記されていること
  - AC-012: 運用中のシステムに影響させない旨の注意書きが記載されていること
- **優先度**: 必須

### REQ-C-005: 動作確認結果のレポート記載
- **種別**: 変更
- **説明**: 各WFの動作確認ステップのフェーズレポートに、動作確認方法（サブエージェント実行 / ユーザーに依頼）、動作確認手順、動作確認結果を記載する構成に変更する。
- **受入基準**:
  - AC-013: レポート記載項目に「動作確認方法」「動作確認手順」「動作確認結果」が含まれること
  - AC-014: 動作確認結果が OK の場合にユーザーへ修正内容と確認結果を報告し承認を得るフローが定義されていること
  - AC-015: 動作確認結果が NG の場合の差し戻しフロー（実装問題→実装ループ差し戻し / 設計問題→設計ステップ差し戻し）が定義されていること
- **優先度**: 必須

### REQ-C-006: ユーザー承認フローの追加
- **種別**: 変更
- **説明**: 動作確認結果が OK の場合、ユーザーに対して修正内容と確認結果を報告し、ユーザーからの承認を得てから次のステップへ遷移する。レポートにユーザー承認結果を記載する。
- **受入基準**:
  - AC-016: レポート記載項目に「ユーザー承認結果」「ユーザー承認の詳細」が含まれること
  - AC-017: 完了条件に「動作確認結果がOK」かつ「ユーザー承認が承認」であることが含まれること
- **優先度**: 必須

### REQ-C-007: 試験書（verification-report.md）の成果物出力
- **種別**: 変更
- **説明**: サブエージェントが動作確認試験を実行した後、試験結果を試験書ファイル（verification-report.md）として出力することを必須とする。試験書には実施した試験項目一覧、各項目の試験手順、各項目の結果（OK/NG）、NG時の詳細情報を含める。出力先は変更WF/bugfix WFではchanges_dir配下、実装WFではスペックフォルダ配下とする。
- **受入基準**:
  - AC-018: サブエージェントが試験実行後に試験書ファイル（verification-report.md）を作成する手順が定義されていること
  - AC-019: 試験書に「試験項目一覧」「各項目の試験手順」「各項目の結果（OK/NG）」「NG時の詳細」が含まれること
  - AC-020: 出力先が変更WF/bugfix WFではchanges_dir配下、実装WFではスペックフォルダ配下であること
  - AC-021: プロンプトテンプレート（REQ-C-002）に試験書出力の指示が含まれていること
- **優先度**: 必須

## 対象外（スコープ外）
- 設計WF、リファクタリングWFへの同様の変更（実装を伴わないWFは対象外）
- Playwright MCP の導入・設定手順の記述
- テストフレームワークの追加・変更
- 動作確認ステップ以外のステップへの変更
- サブエージェントの実装詳細（本要件ではプロンプトテンプレートの定義まで）

※ bugfix WF Phase2 Step10 は本要件に含めるが、コミット 8509340 で既に適用済みである。差分実装は変更WF・実装WFが対象となる。

## 前提条件
- bugfix WF Phase2 Step10 に同様の変更が既に適用済みであり（コミット: 8509340）、その実装パターンを参考にできること
- FSの責務は SKILL やサブエージェントの実行委譲であり、FS自身が直接試験を実行する構成にはしないこと
- 変更対象ファイル:
  - `skills/fs-change-phase2-impl/SKILL.md` の Step 12 セクション
  - `skills/fs-impl-phase4-execution/SKILL.md` の動作確認セクション
  - `skills/fs-bugfix-phase2-impl/SKILL.md` の Step 10 セクション（既に適用済みだが要件定義上は含める）
- 現行の各動作確認ステップは「ユーザー動作検証依頼」として、ユーザーに動作検証を依頼するだけの構成であること

## 関連する既存要件
- **UR-001**: 7つのワークフロー（実装WF / 変更WF / bugfix WFを含む）を提供すること — 全WF横断の動作確認品質向上に寄与
- **UR-005**: 多段コードレビュー（設計準拠＋コード品質の2段階）を提供すること — レビュー後の動作確認品質の強化
- **UR-007**: 進捗管理機構（中断再開・進捗ファイル・フェーズレポート）を提供すること — レポート記載項目の変更に関連
