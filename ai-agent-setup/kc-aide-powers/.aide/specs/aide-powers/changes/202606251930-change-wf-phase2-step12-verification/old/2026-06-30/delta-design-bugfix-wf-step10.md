# 差分設計: bugfix WF fs-bugfix-phase2-impl Step 10

## 変更箇所 1: Step 10 本文へのサブエージェント委譲手順の追記

### 変更理由
現行の Step 10 は「AI Agent 自身が動作確認を行う」と記載されているが、REQ-C-001（サブエージェント委譲必須化）とREQ-C-007（verification-report.md出力）の要件を完全に満たしていない。FSの責務を「プロンプトテンプレート準備→サブエージェント起動→結果受領」に限定する記述と、verification-report.md出力の指示を追記する。

### before
```markdown
## Step 10: 動作検証・ユーザー確認

### 成果物
fs-bugfix-phase2-report.txt

以下を満たすこと
・現在のPhase:
・現在のStep:
・バグが修正された状態になったことを動作確認する。確認の優先順位に従い、まず AI Agent 自身が動作確認を行う
　動作確認方法(Step10):（AI Agent 自身で確認 / ユーザーに依頼）
　動作確認手順(Step10):（実行した再現手順と確認内容の要約）
　動作確認結果(Step10):（OK: バグが再現しないことを確認 / NG: 問題あり）
・動作確認結果が OK の場合、ユーザーに修正内容と確認結果を報告し、ユーザーからの承認を得る
　ユーザー承認結果(Step10):（承認 / 追加確認要求 / NG）
　ユーザー承認の詳細(Step10):

> ⚠️ **動作確認の定義（build/テスト通過だけでは不可）:**
> 「動作確認」とは、**実際にアプリケーションを動作させ、bug-report.md の再現手順を実行してバグが再現しないことを確認する**ことを意味する。build が通る・単体テストが通るだけでは動作確認とみなさない。
>
> **確認の優先順位:**
> 1. **AI Agent が自分で動作確認する（必須）:** アプリケーションを起動し、bug-report.md の再現手順に従って操作し、バグが再現しないことを確認する
> 2. **Web アプリの場合は Playwright MCP を使って必ずブラウザ操作で確認する:** 画面遷移・ボタン操作・表示内容を実際に検証する
> 3. **どうしても自分で確認できない場合のみ:** ユーザーに動作確認を依頼し、ユーザーから「確認OK」の回答を得てから完了とする
>
> 自分で確認できない場合の例: 物理デバイスが必要、外部サービスとの連携が必要、特定の権限が必要 等

### 完了条件
fs-bugfix-phase2-report.txtに、動作確認結果(Step10)が「OK」であり、ユーザー承認結果(Step10)が「承認」であること

### 状態判定
- 動作確認結果(Step10)が「OK」かつユーザー承認結果(Step10)が「承認」の場合 → Step11 へ遷移する
- 動作確認結果(Step10)が「NG」の場合 → 問題の内容を分析し、以下のいずれかに遷移する:
　- 実装の問題（コードの修正が必要）→ Step8（タスク実装ループ）へ差し戻し、追加修正タスクを delta-task-list.md に追記してから再実装する
　- 設計の問題（修正方針自体に問題）→ Step2（修正設計の作成）へ差し戻す
　- 原因分析の問題（原因特定が誤っていた）→ Phase1 からやり直す旨をユーザーに報告し、ユーザー指示に従う
- ユーザー承認結果(Step10)が「追加確認要求」の場合 → ユーザーが指定した追加確認を実施し、結果を報告して再度承認を求める
- ユーザー承認結果(Step10)が「NG」の場合 → ユーザーの指摘内容に基づき上記の差し戻しフローに従う
```

> 動作確認はローカル環境または試験環境で実行し、運用中のシステムに影響を与えてはならない。

### 完了条件

## 変更箇所 2: 成果物テーブルへの追加

### 変更理由
verification-report.md は本変更で明示的に追加される成果物であり、成果物テーブルへの反映が必要。

### before
```markdown
| history.md | {bugfix_dir}/history.md | バグ修正履歴（doc-sync経由で初期作成） |
| fs-bugfix-phase2-report.txt | .aide/tmp/fs-bugfix-phase2-report.txt | fs-bugfix-phase2-implの実行レポート |
```

### after
```markdown
| verification-report.md | {bugfix_dir}/verification-report.md | 動作確認試験書（サブエージェントが出力） |
| history.md | {bugfix_dir}/history.md | バグ修正履歴（doc-sync経由で初期作成） |
| fs-bugfix-phase2-report.txt | .aide/tmp/fs-bugfix-phase2-report.txt | fs-bugfix-phase2-implの実行レポート |
```
