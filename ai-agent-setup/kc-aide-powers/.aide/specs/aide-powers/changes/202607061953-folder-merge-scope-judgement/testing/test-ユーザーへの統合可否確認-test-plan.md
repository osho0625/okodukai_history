# 動作確認試験書：ユーザーへの統合可否確認（機能3）

対象機能: ユーザーへの統合可否確認（folder-merge-check 新Step4、旧Step3）
関連タスク: 0.1

## 試験項目1: 統合可否確認に「関連性の判断結果」「判断理由（根拠）」が追加提示されること

- **状態、条件**: 機能2で関連性「強い」が確定し、新Step4（ユーザーへの確認）に到達した状態
- **確認項目**: ユーザーが、統合可否確認の画面・メッセージに、従来の提示情報（起因元フォルダ・過去の経緯・現在のフォルダ）に加えて「関連性の判断結果」「判断理由（根拠）」の2項目が新たに含まれていることを確認する
- **確認手順**:
  1. 関連性「強い」が確定するシナリオでワークフローを進め、統合可否確認に到達する
  2. AIエージェントが提示する情報を、上から順に確認する
  3. 「起因元フォルダ」「過去の経緯」の直後に「関連性の判断結果」「判断理由（根拠）」が続けて表示され、その後に「現在のフォルダ」が表示されることを確認する
- **確認環境**: aide-powersワークフロー実行環境上での確認、またはAIエージェントによるコードレビューでの確認
- **期待結果**: 提示情報の順序が「起因元フォルダ → 過去の経緯 → 関連性の判断結果（強い） → 判断理由（根拠） → 現在のフォルダ → 統合可否を問う文言」となっていること。SKILL.mdレビューの場合は、Step4の記述順序がこの並びになっていることが目視確認できること

## 試験項目2: 提示情報を確認した上で統合可否（はい／いいえ／その他）を選択できること

- **状態、条件**: 試験項目1と同じ状態（統合可否確認の提示が完了している状態）
- **確認項目**: ユーザーが、判断結果と根拠を含む提示情報を見た上で、「1. はい（統合する）」「2. いいえ（新規フォルダで続行）」「3. その他（自由記述）」の3択から選択できることを確認する
- **確認手順**:
  1. 統合可否確認の提示内容（判断結果・根拠含む）を確認する
  2. 提示された選択肢が3つ（はい／いいえ／その他）であることを確認する
  3. 「1. はい」を選択する
- **確認環境**: aide-powersワークフロー実行環境上での確認、またはAIエージェントによるコードレビューでの確認
- **期待結果**: 「1. はい（統合する）」「2. いいえ（新規フォルダで続行）」「3. その他（自由記述）」の3択が提示され、いずれかを選択して次に進めること

## 試験項目3: 「1. はい」選択時にファイル移動処理（新Step5）へ進むこと

- **状態、条件**: 試験項目2で「1. はい」を選択した状態
- **確認項目**: ユーザーが、「1. はい」を選択した後、実際にファイル移動処理（統合先フォルダへのファイル移動）が開始されることを確認する
- **確認手順**:
  1. 統合可否確認で「1. はい」を選択する
  2. 続く処理として、統合先フォルダに前WFの成果物退避処理、ファイル移動処理が行われることを確認する
- **確認環境**: aide-powersワークフロー実行環境上での確認、またはAIエージェントによるコードレビューでの確認
- **期待結果**: 「1. はい」選択後、統合先フォルダへのファイル移動処理が実行され、ワークフローがエラーなく次のフェーズ（統合先フォルダを使った後続処理）へ進行すること。SKILL.mdレビューの場合は、Step4の「1.はい」の遷移先がStep5と記述されていることが目視確認できること

## 試験項目4: 「2. いいえ」選択時に新規フォルダで続行されること
