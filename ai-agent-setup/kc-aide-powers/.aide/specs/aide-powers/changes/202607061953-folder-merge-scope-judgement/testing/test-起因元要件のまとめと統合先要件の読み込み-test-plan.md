# 動作確認試験書：起因元要件のまとめと統合先要件の読み込み（機能1）

対象機能: 起因元要件のまとめと統合先要件の読み込み（folder-merge-check 新設Step3(a)(b)）
関連タスク: 0.1

## 試験項目1: 優先1（起因元フォルダのトップレベルに現存する(b)分類ファイル）による起因元要件のまとめ

- **状態、条件**: いずれかのワークフロー（変更WF／バグ修正WF／リファクタリングWF）を実行中で、git blame により起因元フォルダが特定され、その起因元フォルダのトップレベルに `change-requirements.md` 等の(b)分類ファイルが現存している状態
- **確認項目**: ユーザーが、フォルダ統合判定に到達した際にAIエージェントが提示する「起因元要件のまとめ」が、起因元フォルダのトップレベルに現存する(b)分類ファイルの内容に基づいていることを確認する
- **確認手順**:
  1. 起因元フォルダのトップレベルに(b)分類ファイル（例: `change-requirements.md`）が存在する状態のリポジトリで、いずれかのワークフローを起動する
  2. ワークフローを進め、フォルダ統合判定（folder-merge-check）が起動される場面まで進める
  3. AIエージェントが提示する起因元要件のまとめ内容を確認する
  4. まとめの内容が、起因元フォルダの `old/{日付}/` 配下の過去文書や `history.md` ではなく、トップレベルの(b)分類ファイルの内容に基づいていることを確認する
- **確認環境**: aide-powersワークフロー実行環境（Kiro IDE等のAI Agentプラットフォーム）上でfolder-merge-checkスキルが呼び出されるシナリオ。実際にワークフローを起動しての確認、またはAIエージェントによるskills/folder-merge-check/SKILL.md記載内容のコードレビューでの確認のいずれでもよい
- **期待結果**: AIエージェントの提示内容（チャット上のまとめ文）に、トップレベルの(b)分類ファイルの内容が反映されていること。SKILL.mdレビューの場合は、Step3(a)優先1の記述が「起因元フォルダのトップレベルに現存する(b)分類ファイル」を最優先の情報源として明記していることが目視確認できること

## 試験項目2: 優先2（old/{日付}/配下の過去要求文書、最新日付優先）による起因元要件のまとめ

- **状態、条件**: 起因元フォルダのトップレベルに(b)分類ファイルが存在せず、`old/{日付}/` 配下に過去の要求文書（複数の日付フォルダを含む）が退避されている状態
- **確認項目**: ユーザーが、トップレベルに(b)分類ファイルがない場合、AIエージェントが `old/{日付}/` 配下の最新日付の要求文書を参照してまとめを行うことを確認する
- **確認手順**:
  1. 起因元フォルダのトップレベルに(b)分類ファイルがなく、`old/2026-01-01/` と `old/2026-05-01/` の2つの日付フォルダが存在する状態を用意する
  2. ワークフローを進め、フォルダ統合判定に到達する
  3. AIエージェントが提示する起因元要件のまとめが、どちらの日付フォルダの内容を参照しているかを確認する
- **確認環境**: aide-powersワークフロー実行環境上でのfolder-merge-check呼び出しシナリオ、またはAIエージェントによるコードレビューでの確認
- **期待結果**: まとめが `old/2026-05-01/`（最新日付）の内容に基づいていること。SKILL.mdレビューの場合は、Step3(a)優先2の記述に「`old/{日付}/` サブフォルダが複数存在する場合は、最新の日付のサブフォルダを優先的に参照する」旨が明記されていることが目視確認できること

## 試験項目3: 優先3（history.md、フォールバック）による起因元要件のまとめと既存除外ルール対象外の確認

- **状態、条件**: 起因元フォルダのトップレベルに(b)分類ファイルがなく、`old/{日付}/` も存在しない状態（`history.md` のみ存在）
- **確認項目**: ユーザーが、優先1・優先2の情報源が存在しない場合にAIエージェントが `history.md`（またはhistory.md不在時は主要ドキュメント概要）を用いてまとめを行うこと、および `old/{日付}/` 参照が既存の除外ルール（設計入力からの除外）の対象外として扱われていることを確認する
- **確認手順**:
  1. 起因元フォルダに(b)分類ファイルと `old/{日付}/` がなく、`history.md` のみが存在する状態を用意する
  2. ワークフローを進め、フォルダ統合判定に到達する
  3. AIエージェントが提示するまとめが `history.md` の内容に基づいていることを確認する
  4. `skills/folder-merge-check/SKILL.md` のStep3(a)本文中「既存の除外ルールとの関係」の記述を確認し、`old/{日付}/` 退避ファイルを本Stepで参照することが除外ルールの対象外と明記されていることを確認する
- **確認環境**: aide-powersワークフロー実行環境上での確認、またはAIエージェントによるコードレビューでの確認
- **期待結果**: まとめが `history.md` の内容に基づいて提示されること。SKILL.md上に「本Stepでの参照はこの保持目的に合致するため、当該除外ルールの対象外である」旨の記述が存在することが目視確認できること
