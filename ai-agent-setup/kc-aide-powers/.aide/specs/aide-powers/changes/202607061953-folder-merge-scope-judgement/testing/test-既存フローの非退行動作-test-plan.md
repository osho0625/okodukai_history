## 試験項目1: Step1（起因元フォルダの存在確認）の早期returnが変更されていないこと

- **状態、条件**: いずれかのワークフローを実行中で、git blame の結果、起因元フォルダのパスが特定されたが、そのフォルダが実際には存在しない（削除済み等）状態
- **確認項目**: ユーザーが、起因元フォルダが存在しない場合に、AIエージェントが「起因元フォルダが見つかりません。新規フォルダで続行します。」と報告し、統合判定プロセス全体（新設Step3含む）を実行せずに現在のフォルダのまま続行することを確認する
- **確認手順**:
  1. 起因元フォルダのパスが特定されるが実際には存在しない状況を用意してワークフローを進める
  2. フォルダ統合判定に到達したときのAIエージェントの報告内容を確認する
  3. 関連性判断（判断結果・根拠の提示等）が行われずに、そのまま現在のフォルダで続行されることを確認する
- **確認環境**: aide-powersワークフロー実行環境上での確認、またはAIエージェントによるコードレビューでの確認
- **期待結果**: 「起因元フォルダ（{パス}）が見つかりません。新規フォルダで続行します。」という報告のみが表示され、関連性判断に関する追加の提示（判断結果・根拠等）は一切表示されないこと
