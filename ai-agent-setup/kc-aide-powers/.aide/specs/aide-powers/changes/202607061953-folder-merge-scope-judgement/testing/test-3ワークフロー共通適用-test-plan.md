# 動作確認試験書：3ワークフロー共通適用（機能5）

対象機能: 3ワークフロー共通適用（変更WF・バグ修正WF・リファクタリングWFからの呼び出し、REQ-C-003）
関連タスク: 0.1

## 試験項目1: 変更WFから呼び出された場合の関連性判断プロセスの実行

- **状態、条件**: 変更WF（`fs-change-phase1-analysis`）を実行中で、Step6「フォルダ統合判定」に到達する状況
- **確認項目**: ユーザーが、変更WFから呼び出された場合でも、新設Step3（関連性判断プロセス）が省略されずに実行されることを確認する
- **確認手順**:
  1. 変更WFを起動し、起因元フォルダが特定される状況を作ってStep6（フォルダ統合判定）に到達する
  2. AIエージェントが「起因元要件のまとめ」「統合先要件（change-requirements.md）の読み込み」「関連性の強弱判断」の各処理を経て、統合可否確認に到達することを確認する
- **確認環境**: aide-powersワークフロー実行環境（変更WF）上での確認、またはAIエージェントによるコードレビューでの確認
- **期待結果**: 変更WFのフォルダ統合判定において、統合可否確認の前に関連性判断プロセス（判断結果・根拠の提示）が実行されていること

## 試験項目2: バグ修正WFから呼び出された場合の関連性判断プロセスの実行

## 試験項目4: リファクタリングWF引き継ぎ経路では新設Step3が実行されないこと（対象外の確認）

- **状態、条件**: リファクタリングWFを引き継ぎ経路（`refactoring-request.md` あり）で起動する状況
- **確認項目**: ユーザーが、引き継ぎ経路では候補特定Step（Step2）自体が素通りされるため、新設Step3（関連性判断プロセス）も実行されないことを確認する
- **確認手順**:
  1. `refactoring-request.md` を用意してリファクタリングWFを起動する
  2. Step2（候補特定）が素通りされることを確認する
