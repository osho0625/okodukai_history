# 工程チェック表

本変更の対象は単一の Markdown スキル定義ドキュメント `skills/folder-merge-check/SKILL.md`（実体: `~/.kiro/skills/folder-merge-check/SKILL.md`）への追記・更新であり、**プログラムコードではない**。そのため全編集タスクを**非プログラム成果物の簡略サイクル（実装 → 設計レビュー → 修正/再レビュー）**で構成する。自動テストは対象外のため、テスト関連の工程列は設けない。

## セルの記号

| 記号 | 意味 |
|------|------|
| `[ ]` | 未実施 |
| `[x]` | 完了（PASS） |
| `[!]` | FAIL（修正中） |
| `[-]` | 該当なし（修正不要だった場合） |

各セルは「状態 / 実行エージェント名」形式で記入する。実行エージェント名は未実施時は `—`、完了時はホワイトリスト（micro-impl-agent / design-review-agent / code-review-agent）のいずれか。

## 監査ルール（ホワイトリスト強制）

- 各セルには「状態 / 実行エージェント名」を記入する。
- 実行エージェント名がホワイトリスト3エージェント（micro-impl-agent / design-review-agent / code-review-agent）以外の場合は ❌ FAIL 扱いとする。
- D-001〜D-003 の「実装」列は micro-impl-agent、「設計レビュー」列は design-review-agent が担当する。
- D-V-001 の「記述レビュー」は受入基準充足確認であり、設計準拠の観点で design-review-agent が担当する。
- ユーザーが事後監査で実行エージェント名列を確認し、ホワイトリスト違反を検出した場合は該当ステップを正しいエージェントで再実行する。

## 備考

- 全タスクは同一ファイル（`skills/folder-merge-check/SKILL.md`）を変更するため、D-001 → D-002 → D-003 → D-V-001 の順で**逐次実行**する（同一ファイル競合回避）。
- 自動テスト・リグレッションテストは対象外（dev-environment.md §7「動作確認の方法」に準拠）。最終的な動作検証はユーザーによる手動検証（実際のフォルダ統合シナリオでの挙動確認）で行う。
