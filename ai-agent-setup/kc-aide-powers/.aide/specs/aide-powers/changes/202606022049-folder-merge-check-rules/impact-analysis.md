## 影響範囲サマリー

### 変更の性質

- **局所的変更**: `skills/folder-merge-check/SKILL.md` の Step 4 セクション内＋完了条件セクション
- **インターフェース変更なし**: Input/Output 不変。呼び出し元フェーズスキルへの波及なし
- **ロジック変更なし**: progress-resume-check / phase-report-check 自体は変更しない
- **ユーザー操作への影響**: 未完了進捗ファイル発見時のみ確認ダイアログが追加（通常フローでは影響なし）

### リスク評価

| リスク | 評価 | 理由 |
|---|---|---|
| 呼び出し元への影響 | 低 | 入出力インターフェース不変 |
| 退避判定の誤動作 | 低 | 既存の (a)/(b) 判定基準と完全に同一の基準を使用 |
| 進捗ファイル退避の副作用 | 低→中 | 未完了状態の進捗ファイルがある場合の誤退避リスク。ユーザー確認必須（REQ-C-002）で対策済み |
| 退避先日付の決定失敗 | 低 | 3段階の優先順フォールバック（history.md → 進捗ファイル日時 → 本日日付）で必ず日付が決定される |
| 既存移動ルールへの退行 | 低 | 「Step 4-事前」は移動ルールの前に挿入される独立サブステップ。既存ルールのロジックに手を加えない |

### 注意事項

1. 統合先の進捗ファイルが未完了状態（途中フェーズが残っている等）の場合は、ユーザーに状況を報告し退避許可を得る必要がある（REQ-C-002 受入基準）
2. 退避先の日付は history.md の最新エントリ日付を優先するが、history.md 不存在時・日付特定不可時のフォールバック（進捗ファイル日時→本日日付）も定義済み
3. 本変更は開発対象（リポジトリ）の skills/ 配下の編集であり、setup.bat 再実行でグローバル領域に反映される（dev-environment.md §0 に準拠）
