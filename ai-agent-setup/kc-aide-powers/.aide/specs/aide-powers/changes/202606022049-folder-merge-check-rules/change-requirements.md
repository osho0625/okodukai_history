# 変更要件定義

## 変更概要

folder-merge-check のフォルダ統合実行時に、統合先フォルダに残存する前WFの (b)分類成果物一式（特に進捗ファイル）を自動的に old/ へ退避するルールを明文化し、progress-resume-check の ALL_COMPLETED 誤判定を防止する。

## 変更要件

### REQ-C-001: 統合実行時の前WF (b)分類成果物一括退避ルールの追加
- **種別:** 機能変更
- **優先度:** Must
- **概要:** folder-merge-check の Step 4（ファイル移動の実行）に、統合実行時に「統合先フォルダに既に存在する前WFの (b)分類成果物一式」を同名衝突の有無を問わず検出し、old/{前WF日付}/ へ一括退避する処理ルールを追加する。現行の Step 4 は「移動元ファイルと同名のファイルが移動先に存在する場合」のみ (a)/(b) 判定を行うが、移動元に同名ファイルが存在しなくても統合先に残る前WF成果物は今回WFの進捗管理に干渉するため、一括退避が必要。
- **受入基準:**
  - folder-merge-check の Step 4 に「統合先フォルダに残存する前WFの (b)分類成果物を一括検出・退避する」手順が明文化されている
  - 退避先は old/{前WF日付}/ であり、日付は統合先 history.md の最新エントリ日付を用いることが定義されている
  - 退避対象の (b)分類成果物の判定基準は既存の Step 4 判定基準と同一であることが確認できる
  - 同名衝突が無い (b)分類ファイルも退避対象に含まれることが明記されている
- **関連PI:** PI-051

### REQ-C-002: 進捗ファイルの退避必須化
- **種別:** 機能変更
- **優先度:** Must
- **概要:** folder-merge-check の統合処理において、統合先に存在する進捗ファイル（change-progress.md / bugfix-progress.md / refactoring-progress.md）を必ず退避対象とすることを明示的に定義する。進捗ファイルは (b)分類の代表例として既に列挙されているが、「統合時に必ず退避しなければならない」という強制ルールとして明記する。
- **受入基準:**
  - 進捗ファイル（change-progress.md / bugfix-progress.md / refactoring-progress.md）が統合先に存在する場合、無条件で old/ へ退避されることがルールとして記述されている
  - 退避後、今回WFの進捗ファイルは phase-report-check write により新規作成されることが前提として明記されている
  - 退避された前WF進捗ファイルが今回WFの progress-resume-check に影響を与えないことが保証される
  - 統合先の進捗ファイルが「全フェーズ✅完了」状態の場合は無条件で退避すること
  - 統合先の進捗ファイルが未完了状態（途中フェーズが残っている等）の場合は、ユーザーに状況を報告し退避許可を得てから退避すること（勝手に退避しない）
- **関連PI:** PI-051

### REQ-C-003: 退避処理の実行タイミング明確化
- **種別:** 機能変更
- **優先度:** Must
- **概要:** 前WF (b)分類成果物の退避処理は、移動元ファイルの移動処理（現行 Step 4 の同名衝突判定処理）の前に実行することを定義する。これにより、移動元ファイルの配置時に統合先が「クリーン」な状態であることが保証される。
- **受入基準:**
  - Step 4 内の処理順序として「前WF (b)分類成果物の退避」→「移動元ファイルの移動」の順で実行されることが定義されている
  - 移動元ファイルの移動時には統合先の (b)分類成果物が既に old/ に退避済みであることが前提として記述されている
- **関連PI:** PI-051

## 変更しないもの（スコープ外の明示）
- folder-merge-check の Step 1〜3（起因元フォルダ存在確認・経緯確認・ユーザー確認）のフローは変更しない
- folder-merge-check の Step 5（history.md 更新）・Step 6（結果返却）は変更しない
- (a)分類（恒久的設計資産）の追記・更新ルートは変更しない
- progress-resume-check / phase-report-check 自体のロジックは変更しない（folder-merge-check 側で退避することにより問題を解消する）
- 統合しない場合（ユーザーが「いいえ」を選択 / 起因元フォルダ不存在）のフローは変更しない

## 前提条件・制約
- 変更対象は skills/folder-merge-check/SKILL.md の Step 4 セクションのみ
- 退避先の日付の決定には統合先 history.md の最新エントリ日付を使用する。history.md が存在しない場合や日付が特定できない場合の代替手段（例: 進捗ファイル内の最終完了日時）も定義する必要がある
- 本変更は全WF種別（変更 / バグ修正 / リファクタリング）に共通して適用される（既存の Step 4 移動ルール注意事項と同一スコープ）
