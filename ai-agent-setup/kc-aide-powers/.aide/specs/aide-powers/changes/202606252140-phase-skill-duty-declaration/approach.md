## 変更方針の詳細

### 1. phase-skill-rules.md に責務宣言ルールセクションを新規追加
- **方針**: 既存セクション「前処理の phase-report-check (verify) 必須実行」の直後（「コンテキスト制約時の対応」セクションの直前）に、新規セクション「各Step・前処理・後処理の実行前の責務宣言」を追加する
- **理由**: 既存の「前処理の phase-report-check (verify) 必須実行」はフェーズ開始時1回の宣言。本追加ルールはStep単位の宣言であり、タイミングが異なるため独立セクションとして追加するのが適切。配置はフェーズ実行フロー順（前処理→各Step実行→後処理→コンテキスト制約対応）に従い、phase-report-check セクションの直後に配置する

### 2. 責務宣言の文言を正確に定義
- **方針**: REQ-C-001 に定義された以下の文言をルール内に引用形式で正確に記載する:
  > 「私の責務はskill記述を正確に実施することです。私は勝手な自己解釈で作業しません、skillの記述に従ってひとつづつ正確に作業します。」
- **理由**: AC-002 により文言の正確性が受入基準として指定されているため

### 3. 宣言タイミング3箇所の明記
- **方針**: 宣言の実行タイミングを以下の3箇所として明記する:
  1. 各Step の実行開始前
  2. 前処理の実行開始前
  3. 後処理の実行開始前
- **理由**: AC-003 により3箇所のタイミングが明確に記載されていることが受入基準

### 4. 省略禁止の明記
- **方針**: 同セクション内に「省略禁止」サブセクションを設け、以下を明記する:
  - 毎回の実行前に必ず宣言すること（累積省略の禁止）
  - 「前のStepで宣言したから不要」「覚えているから不要」等の理由での省略を認めない
- **理由**: REQ-C-002（AC-004, AC-005）により省略禁止と毎回実行が受入基準

### 5. 横断ルールとしての一元管理
- **方針**: ルールは phase-skill-rules.md のみに追加する。各フェーズスキル（`fs-*`）の個別 SKILL.md には埋め込まない
- **理由**: REQ-C-003（AC-006, AC-007）により横断ルールとしての一元管理が要件。phase-skill-rules.md に追加されたルールは全 `fs-*` スキルに自動適用される既存メカニズムを活用する

### 6. version.json のバージョンインクリメント
- **方針**: version を 14→15 に更新し、updated を変更日に更新する
- **理由**: rules-distribute スキルによる配布トリガーとして version 更新が必要。これにより `.kiro/steering/aide-powers-phase-skill-rules.md` 等の配布先が自動更新される
