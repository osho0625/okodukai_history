# 変更要求定義

## 変更概要
- **変更の目的・背景**: 設計ワークフロー全体において、GUI設計フェーズでの画面遷移フロー・イベント制御・状態管理の設計不足、fixモードが存在しないフェーズ（UC分析等）での成果物修正手段の欠如、およびQAレビュー（特にobject-design-qa-agent）の検証精度不足が複合的に発生しており、実装時に画面遷移やユーザー操作に対する挙動が曖昧になる問題、後工程で設計不備が発見されても差し戻せない問題が生じている。設計WF全体のフェーズ間連携を強化し、制御設計の必須化・差し戻し機構の整備・QAレビューの高精度化を行う。
- **変更種別**: 複合

## 要求事項

### REQ-C-001: GUI設計スキルへの画面遷移フローセクション追加
- **種別**: 変更
- **説明**: gui-design スキルのテンプレートに「画面遷移フロー」セクションを追加する。画面遷移フローでは、各画面間の遷移条件（どの操作で何が起きるか）、遷移元・遷移先・トリガー操作・遷移条件を定義する。
- **受入基準**:
  - AC-001: gui-design スキルの SKILL.md に「画面遷移フロー」セクションのテンプレート定義が存在すること
  - AC-002: テンプレート定義に遷移元画面・遷移先画面・トリガー操作・遷移条件の4項目が含まれること
  - AC-003: GUI設計フェーズ実行時に「画面遷移フロー」セクションが成果物として出力されること（省略不可）
- **優先度**: 必須

### REQ-C-002: GUI設計スキルへのイベント制御表セクション追加
- **種別**: 変更
- **説明**: gui-design スキルのテンプレートに「イベント制御表」セクションを追加する。イベント制御表では、各画面のUIコンポーネントに対するイベント（クリック・入力・フォーカス・ホバー等）ごとの処理内容を定義する。
- **受入基準**:
  - AC-004: gui-design スキルの SKILL.md に「イベント制御表」セクションのテンプレート定義が存在すること
  - AC-005: テンプレート定義に画面名・コンポーネント名・イベント種別・処理内容の4項目が含まれること
  - AC-006: GUI設計フェーズ実行時に「イベント制御表」セクションが成果物として出力されること（省略不可）
- **優先度**: 必須

### REQ-C-003: GUI設計スキルへの状態遷移図セクション追加
- **種別**: 変更
- **説明**: gui-design スキルのテンプレートに「状態遷移図」セクションを追加する。状態遷移図では、画面（またはコンポーネント）が取りうる状態と、状態間の遷移トリガー・遷移条件を定義する。
- **受入基準**:
  - AC-007: gui-design スキルの SKILL.md に「状態遷移図」セクションのテンプレート定義が存在すること
  - AC-008: テンプレート定義に状態名・遷移トリガー・遷移条件・遷移先状態の4項目が含まれること
  - AC-009: GUI設計フェーズ実行時に「状態遷移図」セクションが成果物として出力されること（省略不可）
- **優先度**: 必須

### REQ-C-004: architecture-qa-agent への画面遷移・イベント制御検証観点追加
- **種別**: 変更
- **説明**: architecture-qa-agent のレビュープロセスに、GUI設計書における画面遷移フロー・イベント制御表・状態遷移図の存在確認と網羅性検証の観点を追加する。
- **受入基準**:
  - AC-010: architecture-qa-agent の検証項目リストに「画面遷移フローの存在と網羅性」が含まれること
  - AC-011: architecture-qa-agent の検証項目リストに「イベント制御表の存在と網羅性」が含まれること
  - AC-012: architecture-qa-agent の検証項目リストに「状態遷移図の存在と網羅性」が含まれること
  - AC-013: 上記3セクションのいずれかが欠落している場合、FAILとして判定されること
- **優先度**: 必須

### REQ-C-005: object-design-qa-agent への画面遷移・イベント制御整合性検証観点追加
- **種別**: 変更
- **説明**: object-design-qa-agent のレビュープロセスに、オブジェクト設計書のプレゼンテーション層設計がGUI設計書の画面遷移フロー・イベント制御表・状態遷移図と整合していることの検証観点を追加する。
- **受入基準**:
  - AC-014: object-design-qa-agent の検証項目リストに「プレゼンテーション層クラスがイベント制御表の全イベントに対応していること」の確認項目が含まれること
  - AC-015: object-design-qa-agent の検証項目リストに「画面遷移フローで定義された遷移がプレゼンテーション層の実装で表現されていること」の確認項目が含まれること
  - AC-016: object-design-qa-agent の検証項目リストに「状態遷移図で定義された状態がプレゼンテーション層の状態管理で表現されていること」の確認項目が含まれること
  - AC-017: 整合性不足が検出された場合、WARNING以上として判定されること
- **優先度**: 必須

### REQ-C-006: fixモード未実装フェーズへの差し戻し機構追加
- **種別**: 追加
- **説明**: 設計WFのフェーズの中で fix モードが未実装のフェーズ（例: fs-design-phase6-usecase のユースケース分析フェーズ）に対して、後工程（GUI設計・オブジェクト設計・QAレビュー等）で「このフェーズの成果物に不足・誤りがある」と検出された場合に、当該フェーズに差し戻して fix モードで成果物を修正・補完できる仕組みを追加する。
- **受入基準**:
  - AC-018: fix モードが未実装のフェーズスキル（少なくとも fs-design-phase6-usecase）に fix モードのエントリポイントが定義されていること
  - AC-019: fix モードでは、不足と判定された観点（例: 画面遷移・イベント制御に関するユースケース分析の不足）を指定して、該当部分のみを再分析・補完できること
  - AC-020: QAエージェント（architecture-qa-agent, object-design-qa-agent）が成果物の不足・誤りを検出した場合に、差し戻し先フェーズ名と不足観点を明示したレビュー指摘を出力すること
  - AC-021: fix モード実行後、後続フェーズ（差し戻し元）から処理を再開できること
- **優先度**: 必須

### REQ-C-007: object-design-qa-agent のレビュー精度向上
- **種別**: 変更
- **説明**: object-design-qa-agent の検証プロセスを、各レイヤー設計書（domain / app / infra / pres）の作成直後に1ファイルずつレビューする個別ファイルレビュー方式に変更する。現行の横断一括レビュー（ゲート3で全レイヤーをまとめて単一エージェントが一括判定する方式）を廃し、以下3点を実現する: (1) 各レイヤー設計書を作成完了時（Step1〜4の各完了時）に即座に個別レビューする仕組みの導入、(2) レビューを単一エージェントの一括判定ではなくレビュー観点（検証項目カテゴリ）ごとに分割して実行する方式への変更、(3) レビュー内容（検証項目）の追加による網羅性強化。全体整合性レビュー（Step5後のゲート3相当）は残すが、個別ファイルレビューで各層の品質を先に担保した上での整合性確認に役割を限定する。
- **受入基準**:
  - AC-022: 各レイヤー設計書（object-design-domain.md / object-design-app.md / object-design-infra.md / object-design-pres.md）の作成完了時（Step1〜4の各完了時）に、当該ファイル単体を対象とした個別レビューが実行されること
  - AC-023: 個別ファイルレビューがレビュー観点（検証項目カテゴリ）ごとに分割して実行される構造であること（単一エージェントによる一括判定ではないこと）
  - AC-024: 個別ファイルレビューの検証項目が現行の検証項目から追加されていること（追加する具体的な項目は後工程で確定する）
  - AC-025: 各検証項目に対して「検証手順」（何をどう確認するか）が明文化されていること
  - AC-026: 検証結果の判定基準が3段階（PASS / WARNING / FAIL）で定義され、各段階の判定条件が明文化されていること
  - AC-027: 全体整合性レビュー（Step5後）は、個別ファイルレビューで各層の品質が担保済みであることを前提とし、レイヤー間の整合性確認に役割が限定されていること
  - AC-028: 個別ファイルレビューで FAIL 判定が出た場合、後続の Step に進まず当該設計書の修正が行われること
- **優先度**: 必須

### REQ-C-008: ユースケース分析の粒度細分化（全操作網羅）
- **種別**: 変更
- **説明**: fs-design-phase6-usecase のユースケース分析において、現状のユースケースが抽象的すぎるため、画面操作レベルの機能（例: ファイル選択ダイアログでのエクスプローラー起動）が設計から漏れる問題が発生している。全機能・全画面の全ての操作（ボタンクリック・メニュー選択・ダイアログ操作・キーボードショートカット等）を網羅するレベルでユースケースを分析するよう、ユースケース分析スキルの粒度基準を変更する。
- **受入基準**:
  - AC-029: ユースケース分析の粒度基準が「全機能・全画面の全操作を網羅する」レベルで定義されていること
  - AC-030: 各ユースケースが「ユーザーが画面上で行う1つの操作とそれに対するシステムの応答」の粒度で記述されていること（抽象的な機能名ではなく具体的な操作フローとして）
  - AC-031: ユースケース一覧の網羅性チェック基準として「GUI設計書の全画面 × 全コンポーネント × 全操作イベントがユースケースとしてカバーされていること」が定義されていること
  - AC-032: 網羅性チェックで未カバーの操作が検出された場合、ユースケースの追加が必須とされること
- **優先度**: 必須

## 対象外（スコープ外）
- design-review-agent や code-review-agent への検証観点追加（実装フェーズのレビューは本変更のスコープ外）
- 画面遷移フロー・イベント制御表・状態遷移図の具体的な記法（Mermaid等）の標準化
- 既存のGUI設計成果物への遡及適用

## 前提条件
- gui-design スキル（`skills/gui-design/SKILL.md`）が存在すること
- architecture-qa-agent（`agents/architecture-qa-agent.md` および `agents/kiro/architecture-qa-agent.md`）が存在すること
- object-design-qa-agent（`agents/object-design-qa-agent.md` および `agents/kiro/object-design-qa-agent.md`）が存在すること
- 現行の gui-design スキルがGUI設計フェーズ（設計WFフェーズ5）で使用されていること
- fs-design-phase6-usecase スキルが設計WFフェーズ6で使用されていること
