# 変更要求定義: 進捗ファイル完全性チェックフェーズ追加

## 変更概要

### 目的・背景

aide-powers の各ワークフローにおいて、フェーズスキルの実行が正当に行われたかを最終段階で検証する仕組みが不足している。過去にフェーズ実行の偽装（compliance-checker への虚偽情報渡し、前処理省略）が発生したため、ワークフロー完了前にセッション全体の整合性を独立した検証用agentで検査する最終防衛ラインを設ける。

### 変更種別

機能追加（addition）

---

## 要求事項

### REQ-C-001: 最終チェックフェーズスキルの追加（全7WF）

- **種別:** 機能追加
- **説明:** 全7ワークフロー（企画・設計・実装・逆引き・変更・バグ修正・リファクタリング）の最終フェーズとして「進捗ファイル完全性チェック」フェーズスキルを追加する
- **受入基準:**
  - 各WFの進捗テーブルに最終チェックフェーズ行が追加されている
  - フェーズスキルは前処理（progress-resume-check + phase-compliance-check verify）を実行する
  - 前処理完了後、検証用agentを呼び出す
  - 自フェーズの進捗更新はステータス ✅ 完了 のみ（署名なし）
- **優先度:** Must

### REQ-C-002: 検証用agentの新規作成

- **種別:** 機能追加
- **説明:** セッションヒストリー全文を受け取り、ワークフロー実行の正当性を検証する専用agentを新規作成する
- **受入基準:**
  - `.kiro/agents/` 配下にagent定義ファイルが作成されている
  - 以下の3つの検証観点を実装:
    1. セッションヒストリーの自然さ（不自然な飛躍・捏造の兆候がないか）
    2. 各フェーズスキルの実行痕跡（ツール呼び出し・スキルactivate等）が存在するか
    3. ユーザーとの自然なやり取り会話履歴が存在するか
  - compliance-checker への偽装情報渡しの検出ロジックを含む
  - 検証結果を PASS / FAIL で返す
- **優先度:** Must

### REQ-C-003: セッションヒストリー全文の受け渡し

- **種別:** 機能追加
- **説明:** フェーズスキルから検証用agentへ、取得可能なセッションヒストリー全文をテキストとして渡す
- **受入基準:**
  - フェーズスキルがセッションヒストリーをテキスト化して検証用agentに渡す仕組みが定義されている
  - 渡すデータはセッション内で取得可能な全文（切り詰めなし）
- **優先度:** Must

### REQ-C-004: 未完了検出時のリセット動作

- **種別:** 機能追加
- **説明:** 検証用agentが問題を検出した場合、問題のあるフェーズ以降を全リセットしてやり直す
- **受入基準:**
  - 検証 FAIL 時、問題が検出されたフェーズ以降の進捗テーブル行を ⬜ 未着手 にリセットする
  - リセット後、該当フェーズスキルに制御を戻す
  - ユーザーに問題内容とリセット範囲を通知する
- **優先度:** Must

### REQ-C-005: progress_file_path の引き継ぎ

- **種別:** 機能追加
- **説明:** progress_file_path は前フェーズスキルから引き継いだパスを使用する（WFごとに異なるため）
- **受入基準:**
  - 最終チェックフェーズスキルが前フェーズから progress_file_path を受け取る仕組みが定義されている
  - ハードコードされたパスを使用しない
- **優先度:** Must

### REQ-C-006: 誠実性原則の明文化

- **種別:** 機能追加
- **説明:** 検証用agentおよび最終チェックフェーズスキルに「虚偽報告よりも正直な申告を優先する」原則を明文化する。過去にAIエージェントがcompliance-checkerに虚偽のexecution_evidenceを渡して署名を取得した実例があるため、同様の不正を防止する抑止文言を組み込む。
- **受入基準:**
  - 検証用agentの定義に「嘘をつくくらいなら、ユーザーに正直に報告せよ」という原則が明記されている
  - 最終チェックフェーズスキルにも同様の原則が記載されている
  - 既存の phase-compliance-check スキルにもオーケストレータ向けの誠実性原則が追記されている
  - 具体的な過去の不正事例（虚偽execution_evidence、前処理省略の隠蔽）を引用し、同じ過ちを繰り返さないよう警告している
- **優先度:** Must

---

## 対象外（スコープ外）

- 既存の phase-compliance-check スキルのロジック変更
- 既存の compliance-checker agent の変更
- 既存フェーズスキルの前処理・後処理の変更
- progress-resume-check スキルのロジック変更
- 検証用agentによる自動修復（検出のみ、修復はやり直しで対応）

---

## 前提条件

- OCP原則に基づき、既存構造への変更なし（追加のみ）
- progress-resume-check の既存ロジックはそのまま動作する
- 最終チェックフェーズは進捗テーブルに行として存在し、progress-resume-check が認識できる
- 検証用agentは独立したagent定義として作成する（既存agentへの機能追加ではない）

---

## 関連する既存要件

- phase-compliance-check スキル（verify/write モード）
- compliance-checker agent
- progress-resume-check スキル
- 各WFの進捗ファイルフォーマット（progress-file-format.md）
