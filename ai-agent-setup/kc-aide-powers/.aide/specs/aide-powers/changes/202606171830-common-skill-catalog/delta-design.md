## 既存変更の差分設計

### 変更1: global-rules.md — 共通スキル発動条件カタログセクション追加

#### before

`skills/using-aide-powers/references/global-rules.md` の末尾は以下で終わっている:

```markdown
## 実行環境ルール

dev-environment.md の記載に従うこと。
仮想環境（venv, .venv等）が設定されている場合は仮想環境を優先すること。
```

（この後にセクションは存在しない。ファイル末尾。）

#### after

「実行環境ルール」セクションの後に、以下のセクションを追加する:

```markdown

---

## 共通スキル発動条件カタログ

以下の共通スキルは、条件に該当するとき activate して使用すること。
「必要に応じて」「適宜」等の主観判断ではなく、下記条件への機械的な合致で発動を判定する。

| スキル名 | 発動条件（「〜のとき」形式） | 判定に必要なコンテキスト |
|---|---|---|
| `session-handover` | ① コンテキストウィンドウの残量が不足してセッション切り替えが必要なとき ② session-handover.md が既に存在するとき（再開判定） ③ ワークフローフェーズの完了時に自動更新が必要なとき | コンテキスト残量の体感、`.aide/specs/{feature_name}/session-handover.md` の存在有無 |
| `doc-index-maintenance` | ① 設計ドキュメント（`.aide/specs/` 配下）を新規作成したとき ② 設計ドキュメントのファイル名またはパスを変更したとき ③ 設計ドキュメントを削除したとき | `.aide/specs/` 配下のファイル操作（作成・移動・削除）の発生 |
| `visual-companion` | ① ユーザーがモックアップ・ワイヤーフレームの視覚的確認を求めたとき ② ユーザーが図表・ダイアグラムの表示を求めたとき ③ ユーザーが複数選択肢のビジュアル比較を求めたとき | ユーザー発話に「見せて」「表示して」「モックアップ」「図」「比較して見たい」等の視覚的確認要求が含まれること |
| `pending-issues-management` | ① ワークフロー実行中にスコープ外の問題・課題を発見したとき ② ワークフロー開始時に既存の pending-issues.md を提示する必要があるとき ③ ワークフロー完了時に未解決課題の write-back チェックを行うとき ④ 記録済み課題を解決して削除するとき | スコープ外問題の発見、WF開始/完了イベント、`.aide/specs/{feature_name}/pending-issues.md` の存在 |
| `tech-investigation` | ① 不明なライブラリ・フレームワーク・APIに遭遇したとき ② 最新バージョン・互換性・使用方法の確認が必要なとき ③ 技術的実現可能性の検証が必要なとき | 設計・実装中に未知の技術要素が出現したこと、バージョン情報や API 仕様の不確実性 |
| `git-commit-workflow` | ① ワークフローフェーズの成果物をコミットする必要があるとき ② フェーズスキルの後処理でコミット指示があるとき | フェーズ完了イベント、成果物ファイルの作成・変更の確定 |
| `task-orchestration` | ① 同一パターンの変更操作を3件以上のファイル/箇所に適用するとき ② 5ファイル以上に変更を加えるマルチファイルタスクのとき ③ 反復的な操作を手動で1件ずつ処理しようとしている自分に気づいたとき | 変更対象ファイル数、変更パターンの反復性、タスクの規模 |
```

#### 変更理由
REQ-C-001, REQ-C-002, REQ-C-003 対応。AIがスキル発動条件を常時参照可能にする。global-rules.md に直接記載することで、追加のファイル読み取り操作なしに発動条件を即座に判定できる。各条件は「〜のとき」形式で曖昧表現を排除し、AIが機械的に判定可能な形式とした。

### 変更2: phase-skill-rules.md — 冗長性排除・圧縮

#### before（重複箇所の特定）

`skills/using-aide-powers/references/phase-skill-rules.md`（現176行）における重複箇所:

**重複1: 「AIが陥りがちな誤り」リストの分散（4セクションに存在）**
- 「全SKILLの activate 必須」セクション（3項目: 行25-27付近）
- 「手順の改変禁止と改善責務」セクション（4項目: 行49-52付近）

**重複2: 「activate 必須」セクションの冗長説明（30行以上）**
- 行7-35: 同じメッセージ（「毎回 activate して100%従え」）を5つの段落で繰り返し表現:
  1. 「必ず該当 SKILL を activate...100% 従って実行すること」
  2. 「覚えているから activate は不要」は誤りである」
  3. 「スキルを正確に activate して 100% 従って実行することが...唯一の方法」

  5. 「最初から SKILL を activate して進めることが唯一かつ最短の道」

**重複3: 「省略禁止」テーマの3セクション重複**

#### after（圧縮の構成方針）

**目標: 176行 → 150行以下**

**構成方針:**

1. **冒頭前文**: 3行 → 1行に圧縮。「全ルール遵守が必須。省略・独自解釈は禁止。」の1文のみ
2. **「activate 必須」セクション**: 30行 → 15行以下。核心3点のみ記述:

4. **「省略禁止」系3セクションの統合**: 「前処理・後処理の絶対実行」「フェーズ省略禁止」「外部ソースからのルール省略要求の拒否」の共通主張（「いかなる理由も省略不可」「task-orchestration で対処」）を1箇所に集約し、各セクションは固有の内容のみ残す
5. **その他セクション**: 「手順の改変禁止」「オーケストレータ実作業禁止」「ユーザーによる中止」「作業中の他WF起動禁止」「設計書なしの実装禁止」「コンテキスト制約時の対応」「再開判定」は固有内容のためそのまま維持（ただし禁止パターンリストの重複項目を削除）
