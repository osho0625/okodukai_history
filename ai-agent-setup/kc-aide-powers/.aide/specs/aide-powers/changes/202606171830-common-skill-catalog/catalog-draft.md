# 共通スキル発動条件カタログ 作業ドラフト

> このファイルはユーザーとの共同作業で確定した内容と未確定の仮案を記録する作業ファイル。
> 全7スキル確定後、この内容を元に global-rules.md にカタログセクションを書き込む。

## 確定済み（ユーザー承認済み）

### session-handover

- **概要:** セッション間で作業を正確に継続する引継ぎファイルの運用

| # | 発動条件 | 判定コンテキスト |
|---|---|---|
| ① | コンテキスト肥大化により、コンテキストの要約やプロセスの簡易化をシステムから要求されたとき | コンテキスト圧縮通知 |
| ② | セッション開始時に `session-handover.md` が存在するとき | ファイル存在 |
| ③ | ユーザーが引き継ぎ/セッション切り替えを指示したとき | ユーザー発話（「引き継ぎ」「handover」「セッション切り替え」等） |
| ④ | フェーズ完了時のセッション切り替え確認で、ユーザーが「切り替える」と回答したとき | フェーズ完了 + ユーザー回答 |
| ⑤ | ユーザーが作業中断を伝えたとき（退社・PC停止・チャット終了等） | ユーザー発話（「終わる」「落ちる」「退社」「また明日」等） |

### doc-index-maintenance

- **概要:** 設計ドキュメントの作成・変更・削除時に doc-index.md を更新する（登録なきドキュメントは存在しないのと同じ）

| # | 発動条件 | 判定コンテキスト |
|---|---|---|
| ① | `.aide/specs/` 配下の設計ドキュメントを新規作成したとき | ファイル作成操作 |
| ② | 設計ドキュメントのパス・ファイル名を変更したとき | ファイル移動操作 |
| ③ | 設計ドキュメントを削除したとき | ファイル削除操作 |
| ④ | 設計書反映（doc-sync）で設計書本体が更新されたとき | doc-sync 完了イベント |

※ 作業中ドキュメント（changes/ 配下の中間成果物）は登録対象外

### visual-companion

- **概要:** ブラウザで情報をユーザーに分かりやすく表示する。モックアップ・図表・Markdownドキュメントなどを視覚的に表示する。

| # | 発動条件 | 判定コンテキスト |
|---|---|---|
| ① | ユーザーが視覚的な表示を求めたとき | ユーザー発話（「見せて」「表示して」「ブラウザで」等） |
| ② | Markdown・設計書・イメージ・情報量が多い内容など、チャットでは分かりにくい情報をユーザーに提示するとき | 提示対象の性質（構造化ドキュメント、図表、長大なテーブル、比較情報等） |
| ③ | ユーザーに成果物の内容を確認するとき | 成果物ファイルの作成・更新完了 |
| ④ | ユーザーに複雑な内容の判断を仰ぐとき | 選択肢・トレードオフ・設計判断の提示が必要な状況 |

## 未確定（仮案 — ユーザー未承認）

### pending-issues-management

- **概要:** すぐに対処できない課題を忘れないようにpending-issues.mdに登録し、異なるタイミングで実施する

| # | 発動条件 | 判定コンテキスト |
|---|---|---|
| ① | ワークフロー実行中にスコープ外の問題・課題を発見したとき | 現在のWFスコープ外の不具合・設計欠陥・改善点の発見 |
| ② | ユーザーが残件について質問したとき | ユーザー発話 |
| ③ | ワークフロー完了時に未解決課題の書き込み漏れチェックを行うとき | WF完了イベント |
| ④ | 記録済みの課題を解決して削除するとき | 課題解決の確認 |
| ⑤ | ワークフロー完了時 | pending-issues.md |

### tech-investigation

- **概要:** 技術・ライブラリ・APIについて詳しく調査し、設計・実装判断に必要な情報を収集する

| # | 発動条件 | 判定コンテキスト |
|---|---|---|
| ① | ユーザーが技術的な内容について質問したとき | 回答内容の裏付け確認 |
| ② | 技術的な課題が発生したときの情報収集 | 技術的課題の発生 |
| ③ | 企画、要求定義時の実現性を確認するときの裏付け情報収集 | 企画・要求定義フェーズ |

### git-commit-workflow

- **概要:** git コミットをルールに従って安全に実行する（コミットメッセージ生成・ファイル選択・ユーザー承認）

| # | 発動条件 | 判定コンテキスト |
|---|---|---|
| ① | ワークフローフェーズの成果物をコミットする必要があるとき | フェーズ完了イベント、成果物ファイルの作成・変更の確定 |
| ② | フェーズスキルの後処理でコミット指示があるとき | フェーズスキルの後処理定義にコミット指示が含まれること |
| ③ | 変更をcommitするとき | ファイル編集後 |

### task-orchestration

- **概要:** 複雑な要求、大量の要求を正確にこなす

| # | 発動条件 | 判定コンテキスト |
|---|---|---|
| ① | 複数の対象に対して、同様の要求を実行するとき | 変更対象の数（3件以上） |
| ② | 目的到達に段階を踏むような複雑な要求 | 要求の複雑さ（複数ステップ・依存関係あり） |
