# 変更要求定義

## 変更概要
- **変更の目的・背景**: aide-powers には多数の共通スキルが存在するが、AIが適切なタイミングで適切なスキルを自律的に選択・実行するための体系的な発動条件カタログが存在しない。現状では各スキルの SKILL.md に個別に記載された description のみが手がかりであり、AIがスキルの使い忘れや誤選択を起こす原因となっている。共通スキルの発動条件・使用場面を一覧化したカタログを整備し、AIが状況に応じて自律的にスキルを選択・実行できるようにする。加えて、既存の phase-skill-rules.md が同じ主張を繰り返し過ぎて冗長化しており、ノイズが強制力を落としている問題を解消する。
- **変更種別**: 変更（既存の using-aide-powers スキルまたは関連する常時適用ルールに共通スキル発動条件カタログを追加・整備＋既存ルールファイル圧縮）

## 要求事項

### REQ-C-001: 共通スキル発動条件カタログの作成
- **種別**: 追加
- **説明**: 以下の共通スキルについて、発動条件（トリガー条件）・使用場面・判定基準を構造化した一覧（カタログ）を作成する。対象スキル: session-handover, doc-index-maintenance, visual-companion, pending-issues-management, tech-investigation, git-commit-workflow, task-orchestration
- **受入基準**:
  - AC-001: 上記7つの共通スキルそれぞれに対して、発動条件（いつ activate すべきか）と使用場面（どのような状況で必要になるか）が一覧として記載されている
  - AC-002: 各スキルの発動条件が、AIが機械的に判定可能な具体的トリガー（状況・イベント・閾値等）として定義されている（「適宜」「必要に応じて」等の曖昧表現がない）
- **優先度**: 必須

### REQ-C-002: カタログの参照可能性の確保
- **種別**: 変更
- **説明**: 作成したカタログが、AIの通常動作時に参照可能な場所に配置される。具体的には using-aide-powers スキル、または常時適用されるルールファイル（global-rules.md 等）からカタログへの参照パスが記載され、AIがセッション中に発動条件を確認できる状態とする。
- **受入基準**:
  - AC-003: using-aide-powers スキルまたは global-rules.md のいずれかから、カタログドキュメントへの明示的な参照（ファイルパスまたはセクション内記載）が存在する
  - AC-004: AIが通常のワークフロー実行中（フェーズスキル実行中を含む）にカタログの情報にアクセスできる配置になっている
- **優先度**: 必須

### REQ-C-003: トリガー条件の判定可能性
- **種別**: 追加
- **説明**: 各共通スキルのトリガー条件は、AIが現在のコンテキスト（作業状況・直前のイベント・ファイル状態等）から機械的に判定できる形式で記述する。単なる説明文ではなく、条件分岐として利用可能な構造とする。
- **受入基準**:
  - AC-005: 各スキルのトリガー条件が「〜のとき」「〜が発生したら」等の条件文形式で記述されている
  - AC-006: トリガー条件に曖昧な主観判断を要する表現（「複雑だと思ったら」「適切だと判断したら」等）が含まれていない
- **優先度**: 必須

### REQ-C-004: phase-skill-rules.md の冗長性排除と圧縮
- **種別**: 変更
- **説明**: 現在の phase-skill-rules.md は同じ主張を異なる表現で何度も繰り返しており、冗長さがノイズとなって重要な指示が埋もれている。同じルールの言い換え・重複表現を排除し、各ルールを1回だけ明確に述べる簡潔な構成に圧縮する。Claude Code 公式の推奨（200行以下、specific/concise/well-structured）に準拠した分量とする。
- **受入基準**:
  - AC-007: 同一ルールが複数箇所で言い換えられている重複が排除され、各ルールは1箇所でのみ定義されている
  - AC-008: 圧縮後のファイルが200行以下である（Claude Code の steering 推奨サイズ）
  - AC-009: 圧縮によりルールの強制力が低下していない（全ての既存ルールの意図が維持されている）
- **優先度**: 必須

## 対象外（スコープ外）
- 共通スキルの内部ロジック（SKILL.md 本体）の変更
- フェーズスキル（fs-*）の発動条件整理
- 新規共通スキルの追加
- 既存スキルの description フィールドの書き換え
- カタログに基づく自動発動メカニズムの実装（カタログはAIが参照して判断するための情報源であり、プログラム的な自動起動機構ではない）

## 前提条件
- 各共通スキルの SKILL.md が既に存在し、各スキルの用途・動作が定義されている
- using-aide-powers スキルのワークフロー選択セクションが既に存在している
- global-rules.md および phase-skill-rules.md が常時適用ルールとして配布される仕組みが既に動作している

## 関連する既存要件
- `skills/using-aide-powers/SKILL.md`: ハブスキル。ワークフロー選択テーブルおよびルール参照セクションが存在し、カタログの配置先候補
- `skills/using-aide-powers/references/global-rules.md`: 常時適用されるグローバルルール。カタログ参照の追加先候補
- `.aide/specs/aide-powers/program-structure.md`: 共通スキル35個の存在が記載されている（§各フォルダの役割 → skills/）
- `PI-040`（pending-issues.md）: 本変更要求の起源となった課題
