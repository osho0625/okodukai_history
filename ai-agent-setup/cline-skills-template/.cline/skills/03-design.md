# Skill: Design（設計）

## 手順

1. 前フェーズからの差分を確認:
   - ■ 新しく決まったこと
   - ■ 残っている課題
2. 設計を検討する（複数案は合理的な選択肢がある場合のみ）
3. `docs/specs/{feature-name}/design.md` を作成する
4. Decision Log に設計判断を記録する
5. ユーザーに確認 → OKでTask Planningへ

## 出力フォーマット

```markdown
# {機能名} - 設計書

<!-- metadata
status: draft
version: 1.0
-->

## 設計案の比較（複数案がある場合のみ）
### 案A / 案B → 推奨案と理由

## 設計詳細

### ファイル構成
| ファイル | 責務 | 新規/変更 |

### データ設計（該当する場合）
| カラム | 型 | 制約 | 説明 |

### 処理フロー
1. ...

### エラーハンドリング
| 条件 | 表示 | 内部処理 |

### 影響範囲
- `path` — {変更内容}
```

## 禁止事項

- 設計確定前にコードを書かない
- 要件にないものを含めない
- 既存アーキテクチャと矛盾する設計をしない
