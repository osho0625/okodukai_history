# Skill: Requirements（要件定義）

## 手順

1. ユーザーとの会話内容を整理する:
   - 目的: {実現したいこと}
   - ユーザー要求: {具体的に言われたこと}
   - 不明点: {まだ分からないこと}
   - 制約: {言及された制約}
2. 不明点を質問する（必要な項目のみ。文脈から明らかな項目や変更内容に無関係な項目は省略する）:
   - 誰が使うのか
   - 何ができればゴールか（最小スコープ）
   - 既存機能との関係
   - エラー時の挙動
   - データの永続化要否
3. `docs/specs/{feature-name}/requirements.md` を作成する
4. ユーザーに確認 →修正 → 再確認 → OKで次フェーズへ

## 出力フォーマット

```markdown
# {機能名} - 要件定義

<!-- metadata
status: draft
version: 1.0
requires_architecture_review: true/false
-->

## Summary
- 変更対象: {主要ファイル/モジュール}
- DB変更: あり/なし
- API変更: あり/なし
- 未決事項: あり/なし

## 概要
1-3文で。

## ユーザーストーリー
- {誰}として、{何}がしたい。なぜなら{理由}。

## 機能要件
- [ ] FR-1: {具体的かつテスト可能な記述}

## 非機能要件（該当するもののみ）
- パフォーマンス / セキュリティ / アクセシビリティ / 対応環境

## 受入条件
- AC-1: {操作}した時に{結果}が得られること

## スコープ外
- {明示的に除外するもの}

## 前提・制約
- {技術的制約}
```

## 禁止事項

- 要件確定前にコードを書かない
- ユーザー確認なしに次フェーズに進まない
- 要件を勝手に追加・削除しない
