# Skill: Architecture Review

## 手順

1. requirements.md の概要を確認する
2. 変更対象周辺の実装パターンのみ確認する（リポジトリ全体を探索しない）
3. 下記チェックリストを実施する
4. `docs/specs/{feature-name}/architecture-review.md` に記録する
5. ユーザーに報告 → Designフェーズへ

## 出力フォーマット（チェックリスト）

```markdown
# {機能名} - アーキテクチャレビュー

## チェック結果
- [ ] 既存ディレクトリ構成に収まるか: ✅ / ⚠️
- [ ] 既存データフローに乗せられるか: ✅ / ⚠️
- [ ] 既存命名規則・パターンに合うか: ✅ / ⚠️
- [ ] 既存技術スタックで実現可能か: ✅ / ⚠️
- [ ] デグレリスク: 低 / 中 / 高
- [ ] 共有リソースへの影響: なし / あり

## 影響ファイル
- {パス} — {影響}

## 推奨方針
- {一文}

## リスク（あれば）
- {一文}
```

## 禁止事項

- このフェーズでコードを書かない
- 問題を無視してDesignに進まない
