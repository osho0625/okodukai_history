# テスト方針（テスト作成時のみ参照）

## 原則

- 新機能 → テスト必須
- バグ修正 → 再現テストを先に書く
- テスト落ちたまま次に進まない

## 粒度

| レベル | 対象 | 頻度 |
|--------|------|------|
| ユニット | 関数・メソッド | 全変更 |
| 統合 | モジュール間 | 機能追加時 |
| E2E | ユーザー操作 | 重要フロー |

## 書き方

- プロジェクト既存のテストスタイルを優先する
- AAA（Arrange → Act → Assert）
- ユニット: 1テスト = 1アサーション
- 統合: グループ化OK
- テスト間の依存なし

## 優先順位

1. ビジネスロジック
2. 境界値・エッジケース
3. エラーケース
4. 正常系

## 書けない場合

スキップ禁止。記載: 理由 / 代替確認方法 / 手動確認結果
