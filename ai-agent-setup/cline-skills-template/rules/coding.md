# コーディング規約

プロジェクトに配置する場合は `.clinerules/coding.md` にコピーする。

## 一般原則

- 既存コードのスタイルに合わせる（一貫性優先）
- 新しいライブラリ・フレームワークの導入は事前にユーザーに確認する
- YAGNI: 今必要ないものは作らない
- Rule of Three: 2回までのコピペはOK、3回目で共通化を検討する（過剰抽象化を防ぐ）

## 命名規則

- 変数・関数: camelCase
- クラス・コンポーネント: PascalCase
- 定数: UPPER_SNAKE_CASE
- ファイル名: kebab-case（プロジェクトの慣習に従う）

## コメント

- 「何をしているか」ではなく「なぜそうしているか」を書く
- 複雑なビジネスロジックには必ずコメントを残す
- TODOコメントは残さない（今解決するか、issueに切り出す）

## エラーハンドリング

- try-catch で握りつぶさない（最低限ログを出す）
- ユーザー向けのエラーメッセージは具体的かつ親切に
- APIエラーはステータスコードに応じた適切な処理を行う

## セキュリティ

- ユーザー入力は必ずサニタイズする
- パスワード・APIキーをソースコードにハードコードしない
- innerHTML の使用は最小限に（XSS対策）
