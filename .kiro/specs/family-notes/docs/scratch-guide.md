# 🎮 Scratchでゲームをつくろう！

これは、はるちかがScratch（スクラッチ）でゲームを作るためのガイドだよ。
答えは書いてない。ヒントだけ読んで、自分で考えて作ってみよう！

わからなくなったら、Scratchで他の人のゲームの「中を見る」をしてみよう。
それでもわからなかったら、パパに「ここまではできたんだけど」って見せてね。

**▼をタップして、各ステップを開いてプログラミングを始めよう！**

---

<details>
<summary>🌟 はじめに：Scratchってなに？</summary>

Scratchは、ブロックを組み合わせてゲームやアニメーションを作れるツールだよ。
文字を打つプログラミングとちがって、ブロックをドラッグ＆ドロップするだけ！

**Scratchのサイト：** https://scratch.mit.edu/

</details>

<details>
<summary>📝 Scratchの画面の見かた</summary>

Scratchエディタ（https://scratch.mit.edu/projects/editor/）をひらくと：

| 場所 | なにがあるか |
|------|------------|
| 左がわ | ブロック置き場（ここからブロックを選ぶ） |
| 真ん中 | コードエリア（ここにブロックを並べる） |
| 右上 | ステージ（ゲームが動く画面） |
| 右下 | スプライト一覧（キャラクターの管理） |

**スプライト** = ゲームに出てくるキャラクターやもの
**ステージ** = ゲームの背景（はいけい）
**コスチューム** = スプライトの見た目

</details>

<summary>🐱 ステップ0：まずはネコを動かしてみよう（10分）</summary>

はじめてScratchをさわるなら、まずこれをやろう！

### ミッション

ネコを 🏁 ボタンで動くようにしよう。

### ヒント

- 「イベント」カテゴリに、ゲームを始めるためのブロックがあるよ
- 「動き」カテゴリに、スプライトを動かすブロックがあるよ
- ブロックを下につなげると、上から順番に実行されるよ

### チャレンジ

できたら次のことを考えてみよう：

1. ネコを **ずっと動かし続ける** にはどうする？（「制御」カテゴリを見てみよう）
2. 画面のはしに行ったら **跳ね返る** にはどうする？（「動き」カテゴリの下のほう）
3. **矢印キーで動かす** にはどうする？（「調べる」カテゴリに、キーの情報がある）

</details>

<details>
<summary>🏰 ステップ1：迷路ゲームをつくろう</summary>

### ゴール

矢印キーでキャラを動かして、壁にぶつからずにゴールまでたどりつくゲーム！

### 考えること

この4つの問題を解決すればゲームになる：

1. **迷路の背景**をどうやって作る？
2. キャラを**矢印キーで上下左右に動かす**にはどうする？
3. **壁にぶつかったらスタートにもどす**にはどうする？
4. **ゴールに着いたらクリア**にするにはどうする？

### ヒント1：迷路をかく

- ステージ（右下）を選んで「背景」タブで絵が描ける
- 壁を **黒** 、道を **白** 、ゴールを **赤** のように色を分けると、あとで使いやすい
- 壁は太めにかくのがコツ（細いと判定がむずかしくなる）

### ヒント2：キャラを矢印キーで動かす

- 使うブロックのカテゴリ：「制御」「調べる」「動き」
- キーの入力をチェックするブロックは「調べる」にある
- 上下はy座標、左右はx座標だよ
- 「ずっと」チェックし続けないと、1回しか動かないよ

### ヒント3：壁に当たったらもどす

- 「調べる」カテゴリに「色に触れた」というブロックがある
- 色を指定するには、スポイトで画面の色をクリックすればOK
- 「もし壁の色に触れたなら…」のあと、何をすればスタートにもどる？

### ヒント4：ゴール判定

- ゴールの色も「色に触れた」で判定できる
- ゴールに着いたら何をしたい？（メッセージを出す？止める？）
- 「見た目」カテゴリに、しゃべらせるブロックがあるよ

### 🎉 完成チェック

- [ ] 矢印キーで上下左右に動く
- [ ] 壁にぶつかるとスタートにもどる
- [ ] ゴールに着いたら「クリア」と表示される

### 💪 もっとよくするアイデア

- タイマーでクリアタイムを測れる？
- ステージを2つ作って、次の迷路に進めたら？
- 動く障害物を足したら？

</details>

<details>
<summary>🚪 ステップ2：脱出ゲームをつくろう</summary>

### ゴール

部屋にあるアイテム（鍵）を見つけて、ドアを開けて次の部屋にすすむゲーム！

### 考えること

1. **複数の部屋**をどうやって表現する？
2. **鍵を持っているかどうか**をどうやって記録する？
3. 鍵を持っていないときにドアをクリックしたら**「開かない」と言わせる**
4. 鍵を持っているときにドアをクリックしたら**次の部屋に行く**

### ヒント1：部屋を作る

- ステージの「背景」は複数持てる。背景1枚＝1部屋として使える
- 「見た目」カテゴリに背景を切り替えるブロックがある

### ヒント2：アイテムを持ってるかどうかを記録する

- **「変数」** というしくみを使う
- 「変数」カテゴリで新しい変数を作れる
- 変数は「数字を入れる箱」。鍵を持ってたら1、持ってなかったら0にしよう
- 鍵のスプライトをクリックしたとき、変数を変えればOK

### ヒント3：ドアの判定

- 「もし〜なら」ブロックの中にさらに「もし〜なら」を入れることができる
- 条件をどう組み合わせる？
  - **クリックされた**（「調べる」に触れた系のブロック）
  - **かつ** 鍵の変数が1（「演算」カテゴリに比較ブロック）

### ヒント4：スプライト同士の連絡

- 部屋が変わったとき、新しい部屋の鍵やドアを「表示する」必要がある
- 「イベント」カテゴリに **メッセージ** というしくみがある
- あるスプライトが「メッセージを送る」→別のスプライトが「メッセージを受け取ったとき」動く

### 🎉 完成チェック

- [ ] 鍵をクリックするとゲットできる
- [ ] 鍵なしでドアを触ると「開かない」と言われる
- [ ] 鍵ありでドアを触ると次の部屋に行く
- [ ] 最後の部屋でクリア画面が出る

### 💪 もっとよくするアイデア

- なぞなぞを出して、正解したらドアが開くようにしたら？（「調べる」→「〇〇と聞いて待つ」）
- 制限時間をつけたら？
- 隠しアイテムを探すゲームにしたら？

</details>

<summary>🚀 ステップ3：シューティングゲームをつくろう</summary>

### ゴール

自分の宇宙船を左右に動かして、弾を撃って敵をたおすゲーム！

### 考えること

1. **自機を左右キーで動かす**（ステップ1でやったのと似てる！）
2. **スペースキーで弾を撃つ** — 弾は何発も出るけど、スプライトは1つ。どうする？
3. **敵が上から降ってくる** — ランダムな場所に、何体も出てくる。どうする？
4. **弾が敵に当たったらスコアUP** — 当たり判定と変数
5. **敵が自機に当たったらゲームオーバー**

### ヒント1：弾を何発も撃つには？

ここが一番大事なポイント！「**クローン**」を使う。

- **クローン** ＝ スプライトのコピーを作ること
- 「制御」カテゴリに「自分自身のクローンを作る」ブロックがある
- 「クローンされたとき」ブロックで、コピーが生まれた瞬間の動きを決められる
- 元のスプライトは「隠す」で見えなくしておいて、クローンだけが画面に出るイメージ

**考えてみよう：**
- クローンが生まれたら、どこに出現させたい？（自機の位置？）
- クローンはどの方向に動く？（上？下？）
- 画面の外に行ったクローンはどうする？（「このクローンを削除する」）

### ヒント2：敵もクローンで作る

- 敵もクローンで次々に出す。弾と同じ考え方！
- ちがうのは：出現場所が**ランダム**、動く方向が**下**
- 「演算」カテゴリに「乱数」ブロックがあるよ

### ヒント3：当たり判定

- 「調べる」カテゴリに「〇〇に触れた」ブロックがある
- 敵のクローンが「弾に触れた」かチェックすればいい
- 当たったら：スコアを+1して、そのクローンを消す

### ヒント4：スコア

- 「変数」を作って「スコア」と名付ける
- 当たるたびに1増やす
- ステージ上に自動で表示される

### 🎉 完成チェック

- [ ] 自機が左右に動く
- [ ] スペースキーで弾が上に飛ぶ
- [ ] 敵が上からランダムに落ちてくる
- [ ] 弾が敵に当たるとスコアが増えて敵が消える
- [ ] 敵が自機に当たるとゲームオーバー

### 💪 もっとよくするアイデア

- 速い敵、ジグザグに動く敵を作ったら？
- パワーアップアイテム（取ると弾が大きくなる）
- ボス戦（たくさん弾を当てないと倒せない敵）
- BGMと効果音をつけたら？（「音」タブで追加できる）

</details>

<summary>🦘 ステップ4：アクションゲームをつくろう</summary>

### ゴール

ジャンプして足場をのぼっていくゲーム！（マリオみたいなやつ）

### 考えること

1. **重力** — キャラが常に下に落ちる。足場に乗ると止まる。
2. **ジャンプ** — 上に飛んで、重力でまた落ちてくる。
3. **地面の判定** — 足場の上に立てる。めり込まない。
4. **ゴールとやられ判定** — ゴールでクリア、トゲに当たったらやり直し。

### ヒント1：重力のしくみ

これがアクションゲームで一番むずかしい部分。じっくり考えよう。

**方針：**
- 「y速度」という変数を作る
- 毎フレーム（ずっとの中で）、y速度を少し減らす（-1するとか）→ だんだん速く落ちる
- y座標を「y速度」ぶんだけ変える
- これだけで「落下」になる！

**考えてみよう：**
- 地面に触れたら何をすればいい？（y速度をどうする？）
- ジャンプするとき、y速度をどうすればいい？（プラスにする？マイナスにする？）
- 空中でジャンプできないようにするには？（「地面にいるかどうか」を記録する変数が必要？）

### ヒント2：地面と足場

- 背景に地面と足場を **同じ色** で描く
- 「色に触れた」で地面判定する
- めり込み問題：地面に触れたら、触れなくなるまでy座標を+1していく

### ヒント3：ジャンプのコツ

- ジャンプ＝「y速度を一気にプラスにする」
- すると上に飛ぶ → でも毎フレーム-1されるから、だんだん遅くなって、最後は落ちる
- 現実の重力と同じしくみ！

### ヒント4：二段ジャンプを防ぐ

- 地面にいるときだけジャンプできるようにしたい
- 「地面についてる」という変数（0か1）を作る
- 地面に触れてるとき1、空中では0
- ジャンプの条件：「スペースが押された」**かつ**「地面についてる＝1」

### 🎉 完成チェック

- [ ] キャラが下に落ちる（重力がきいてる）
- [ ] 地面や足場の上に立てる（めり込まない）
- [ ] スペースでジャンプできる
- [ ] 空中ではジャンプできない
- [ ] トゲに当たるとスタートにもどる
- [ ] ゴールでクリア

### 💪 もっとよくするアイデア

- 動く足場（左右にゆれる足場）
- コインを集めたらスコアが増える
- ステージ2、3と作ったら？
- 壁ジャンプ（壁に触れてるときにジャンプできるようにしたら？）

</details>

<summary>🧰 こまったときのヒント</summary>

### ブロックが見つからない！

| やりたいこと | カテゴリ | 色 |
|------------|---------|-----|
| 動かす、座標 | 動き | 青 |
| 見た目を変える、しゃべる | 見た目 | むらさき |
| 音を鳴らす | 音 | ピンク |
| くりかえし、もし、クローン | 制御 | オレンジ |
| キーが押された、色に触れた | 調べる | 水色 |
| 計算、乱数、比較 | 演算 | 緑 |
| 変数、スコア | 変数 | オレンジ（濃い） |
| 旗クリック、メッセージ | イベント | 黄色 |

### うまく動かないとき

1. **少しずつ作る** — 全部いっぺんに作らない。1つ機能を足すたびにテストしよう
2. **ブロックの順番を確認** — 上から順に実行されるよ
3. **他の人の作品を見る** — https://scratch.mit.edu/explore/projects/games で検索して「中を見る」で、どうやって作ってるか見れる
4. **パパに「ここまではできた」と見せる** — 何ができてて、何ができてないかを説明するだけで解決することもある

### 大事なこと

- **すぐにできなくて当たり前！** プロのゲーム開発者も何回も失敗して作ってる
- **エラーは敵じゃない** — 「ここがおかしいよ」って教えてくれてるだけ
- **他の人のコードを見るのはずるくない** — プログラマーはみんなやってる。見て学んで、自分のゲームに使おう

</details>
